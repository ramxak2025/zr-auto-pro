# swift-native-module

## When to use

- New native UIView / SwiftUI view that JS can mount via `requireNativeViewManager`.
- Adding props / events to an existing local Expo Module.
- iOS-26-only material upgrades.

## Files / docs to read first

- `mobile/modules/autexa-liquid-glass/expo-module.config.json`
- `mobile/modules/autexa-liquid-glass/ios/AutexaLiquidGlassModule.swift` (Module declarations, View bindings)
- `mobile/modules/autexa-liquid-glass/ios/AutexaLiquidGlass.podspec`
- `mobile/modules/autexa-liquid-glass/src/index.ts` — JS exports
- An existing native view as template: `AutexaKassaButtonView.swift` or `AutexaLiquidGlassTabBarView.swift`
- `mobile/CLAUDE.md` for the autolinking story

## Workflow

1. Add the Swift file under `mobile/modules/<module-name>/ios/`. Subclass `ExpoView`. Required init signature: `public required init(appContext: AppContext? = nil)`.
2. Register the view in `<module>/ios/<Module>.swift`: a new `class XxxModule: Module` with `Name("Xxx")` and `View(XxxView.self) { Prop(...) Events(...) }`.
3. Add the module name to `expo-module.config.json` `apple.modules`.
4. Add a JS wrapper under `<module>/src/`: `requireNativeViewManager('Xxx')`, fall back gracefully when missing or on Android.
5. Re-export from `<module>/src/index.ts`.
6. Use `NSClassFromString("UIGlassEffect") as? NSObject.Type` for iOS 26 lookups.
7. Avoid colliding with UIView built-in properties (e.g. `focused` is reserved — use `kassaFocused`, etc.).
8. Run `npx expo prebuild --platform ios --clean`, then `cd ios && pod install`. Verify the file compiles with `xcodebuild -workspace ios/Autexa.xcworkspace -scheme Autexa -sdk iphonesimulator build`.

## Acceptance criteria

- xcodebuild SUCCEEDED.
- Module appears in Pods autolinking log.
- JS hot-load works on simulator.

## Checks

- `expo prebuild --clean`, `pod install`, `xcodebuild`, app installs into simulator.

## Risks

- Forgetting to register the new module in `expo-module.config.json` ⇒ JS `requireNativeViewManager` returns null silently.
- Subclassing UIView and reusing reserved property names ⇒ build failures (e.g. `focused`).
- Hard SDK references (use runtime lookup for iOS 26 APIs).

## Forbidden

- Editing files under `mobile/ios/` directly (regenerated by prebuild).
- Touching backend / shared types.
- Skipping `pod install` after a `podspec` change.

## Final report format

1. Native files added. 2) Module registrations updated. 3) JS bindings exported. 4) Build status. 5) What user verifies on iPhone.
