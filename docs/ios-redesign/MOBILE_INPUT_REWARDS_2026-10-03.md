# Поля ввода, значки и денежные уведомления — 2026-10-03

## Причины и исправления

- В `ExpensesScreen` заголовок FlashList передавался функцией, заново создаваемой при каждом рендере. React воспринимал её как новый тип компонента: поля произвольного периода размонтировались после символа. Теперь передаётся JSX-элемент со стабильным типом; дата обновляется без замены нативного TextInput.
- Общая `Modal` рассчитывала размеры один раз по `Dimensions`, независимо от клавиатуры, поворота и safe area. Теперь карточка ограничена доступным внутренним контейнером, тело сжимается и прокручивается, длинный заголовок оставляет место кнопке закрытия.
- Emoji наград размером 26/36/48 наследовали `Typography.body.lineHeight=22`. Добавлены соответствующие строки 36/48/64, ограничен только множитель декоративных emoji (1.3); подписи продолжают учитывать системный размер текста. Форма награды использует `KeyboardAwareScroll`, экранные границы и safe area. На iOS переход из «Все значки» в выдачу ждёт `onDismiss`, чтобы не презентовать вторую нативную модалку поверх закрывающейся первой.
- Рабочий `SalaryReceivedModal` получил безопасную высоту с учётом вырезов/панелей, прокручиваемое тело, явно ограниченную ширину суммы и уменьшение шрифта для больших значений. Значения больше не округляются до рублей: 0.01 ₽, 12.50 ₽ и крупные суммы сохраняют копейки. Размеры конфетти берутся из текущего окна. Неиспользуемый `SalaryEnvelopeAnimation` не подключался и не считался рабочим путём.

## Штраф у получателя

Раньше сервер отправлял push с `kind: 'penalty'`, а мобильный listener проверял только `data.type` и зарплатные категории. Отдельного надёжного in-app inbox штрафов не было. Теперь:

1. Миграция `175_penalty_viewed.sql` добавляет `salary_penalties.viewed_at`. Исторические строки получают timestamp при добавлении столбца, после чего default снимается: новые штрафы остаются непросмотренными. Такой backfill не зависит от RLS-фильтра UPDATE, повторный запуск не гасит новые уведомления. Денежные поля не меняются.
2. `GET /salary/penalties/unviewed` возвращает только собственные непросмотренные штрафы по JWT tenant + user, включая прежние месяцы/филиалы. `POST /salary/penalties/:id/viewed` ставит первую отметку через `COALESCE`, проверяя одновременно id, tenant и получателя. Удалённый/чужой штраф даёт 404.
3. `SalaryNotificationProvider` перепроверяет сервер после входа, foreground и push (`type` или `kind`). Сумма/причина берутся из API, не из push. Повторный refetch одного id не перезапускает эффект. Удаление штрафа очищает уведомление после успешного ответа; отказ сети не стирает уже открытые данные.
4. Один общий нативный modal показывает выплаты и штрафы по очереди. У штрафа отдельная иллюстрация: облако, дождь, грустное лицо и мягкое опускание. Нет конфетти, пружинного входа, зелёной кнопки или success-haptic. Для Reduce Motion — статичная иллюстрация и плавное появление, настройки отслеживаются без оптимистичного запуска движения до ответа ОС.
5. «Понятно» ставит read receipt в очередь, «Позже» только откладывает показ до следующего входа/запуска. Очередь хранится по tenant + user; старый безымянный общий ключ намеренно не присваивается текущему аккаунту. 401/408/429 и сетевые ошибки сохраняют ack. Перед доставкой и после каждого ожидания проверяется сессия; axios-клиент дополнительно захватывает bearer/epoch синхронно до Promise-интерсепторов. Чужой токен нельзя унаследовать даже между созданием запроса и его dispatch.

Новому мобильному inbox нужен backend с миграцией 175. До обновления backend ответ 404 нового endpoint не препятствует прежнему пути выплат. Изменения shared-контракта аддитивны; веб-потребители не обязаны использовать новые методы.

- Jest: `salaryAckQueue`, `salaryNotices`, `axiosAuthExpiryRace` — 35 тестов успешно. - `backend`: build и `tsc --noEmit --incremental false` — успешно. `salary-penalty-inbox.test.cjs` — 4 теста: контроллер + сервис с mocked pool, tenant/user условия SQL, первый timestamp, 404, структура backfill. Целевой lint — 0 ошибок, 31 существующее предупреждение `any`.

## Проверка на устройствах перед публикацией

Нативный рендер/клавиатура не подтверждены одним TypeScript/Jest прогоном. На iOS и Android нужно пройти:

- Расходы → произвольный период → непрерывный ввод нескольких символов в обе даты, удаление и вставка; фокус не теряется.
- Создание награды, затем «Все значки» → «Выдать новый значок»; emoji целые, header/закрытие доступны, нижнее поле видно с клавиатурой.
- Маленький экран/landscape, крупный системный текст; выплата, аванс, штраф 0.01 / 631000.50 / 9999999999.99 ₽ с длинной причиной.
- Новый штраф у мастера: приложение открыто, в фоне, после перезапуска. Нажать «Понятно» без сети, восстановить связь; повторного эффекта нет. Повторить со сменой аккаунта до возврата сети.
- Reduce Motion включён до запуска и переключён при открытом уведомлении; штраф не получает праздничного оформления.

Production, версии приложений, App Store/Play, секреты и native build-конфигурация не менялись этим блоком.
