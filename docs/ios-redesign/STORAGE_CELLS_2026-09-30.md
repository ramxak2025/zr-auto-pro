# Адресное хранение на складе: ячейки в мобильном приложении (2026-09-30)

Спека — `docs/specs/2026-09-30-STORAGE_CELLS.md` (§0 «Модель», §5 «Mobile», §6 «Проверки»;
блоки «Уточнено в фазе 0» приоритетнее основного текста). Контракт закрыт заранее и в этой
задаче не менялся: `shared/types/index.ts` (`StorageCell`, `StorageCellError`, поля
`Product.storageCellId / storageCellCode / storageCellName`), `shared/api/types.ts`
(`storageCellId` в create/update товара, запросы модуля ячеек), `shared/api/createServices.ts`

`generateCellCodes`, `countCellCodes`, `expandRacks`, `MAX_BULK_CELLS = 2000`,
`MAX_RACKS = 100`). Фабрика подключена как `storageCellsApi` в `mobile/src/api/services.ts`.

Затронуто в `mobile/src/`:

- новые: `screens/StorageCellsScreen.tsx`, `components/StorageCellPickerModal.tsx`,
  `components/StorageCellChip.tsx`, `hooks/useStorageCells.ts`, `utils/storageCellsUi.ts`;

  `constants/productFields.ts`, `utils/persistentCache.helpers.ts`,

## Проблема

Товар лежит на складе «где-то»: кладовщик ищет запчасть по памяти, мастер в Кассе не знает,
откуда её брать. Владельцу нужен адрес: у товара есть ячейка вида `A-01-03`, по коду ячейки
товар находится поиском, код виден в списке склада, в карточке товара и в подборе товара в
Кассе, а сами ячейки заводятся быстро — сеткой «стеллажи × полки × места», а не по одной.

Модель (спека §0): ячейка принадлежит складу; один товар — одна ячейка; код нормализуется
(регистр и лишние пробелы не важны); удалить можно пустую ячейку либо с переносом товаров в
другую ячейку того же склада / с откреплением адреса; копия товара на другом складе адреса не
получает. Требование продукта: у компании без ячеек ни один экран не меняется.

## Решение

### Данные и кэш

`hooks/useStorageCells.ts` — один запрос на склад: ключ `['storage-cells', warehouseId]`.
Ключ добавлен в whitelist `persistentCache` (`PERSISTED_KEYS`, `VARIANT_CAPS['storage-cells'] = 4`):
пикер ячейки и экран «Ячейки хранения» на холодном старте открываются уже с данными, склад без
ячеек отсекает общий guard «пустая коллекция не персистится». Глобальный
`placeholderData: prev => prev` не отключён: для этого запроса он сужен до «предыдущие данные
ТОГО ЖЕ склада» — при смене склада ячейки чужого склада не мелькают и не доступны для выбора
(сервер такой выбор отклонил бы кодом `STORAGE_CELL_WRONG_WAREHOUSE`).

Каждая мутация ячеек и адреса инвалидирует `['storage-cells']` (счётчик товаров в ячейке) и,
если менялся адрес товара, ещё `['products']`, `['all-products-check']`, `['product']`.
`App.tsx` показывает глобальный тост ошибки только для мутаций без собственного `onError`, поэтому
у всех мутаций ячеек `onError` свой — понятный текст отказа (`utils/storageCellsUi.ts`,
разбор по `code` верхнего уровня тела ответа, а не по тексту).

`PRODUCT_LIST_FIELDS` (`?fields=` списка склада) дополнен `storageCellId,storageCellCode`: без
этого проекция не отдала бы код в строку. Ключ запроса товаров остаётся прежним — кэш и
предзагрузка после логина (`AuthContext.prefetchAfterLogin`) работают как раньше.

### Чип кода — `StorageCellChip`

Одна плашка на склад, подбор в Кассе и инвентаризацию: моноширинный код (`VIN_MONO_FONT`),
11 pt, приглушённая заливка `palette.bg.muted`, `flexShrink` + `maxWidth`: при нехватке места
ужимается плашка, а не цена и не остаток; высота 16 pt, строка склада остаётся 76 pt. Без кода
компонент возвращает `null` — строка товара без адреса рендерится как раньше. Токенов
`iosCaption` / `fillTertiary` из спеки в теме нет; вместо них — `bg.muted` и mono-шрифт 11 pt.

### Пикер ячейки — `StorageCellPickerModal`

Модалка `pageSheet` (как `FolderPickerModal`): ячейки одного склада, поиск по коду и подписи,
«Без адреса», «+ Создать ячейку «…»» — код вводится здесь же, ячейка создаётся и сразу
выбирается (склад без ячеек не упирается в отдельный экран). Закрывается сама после выбора
(`haptic('select')`). `excludeCellId` и `allowClear={false}` — режим «куда перенести товары».

### Управление ячейками — `StorageCellsScreen`

Вход: Склад → кнопка операций (⇄ в шапке, видна только при `warehouse_manage`) → «Ячейки хранения». Экран в
стеке «Склад», нижний бар остаётся. Чипы складов (main / defect / used), поиск по коду и подписи,
список (FlashList): код · подпись · «N товаров» / «Пусто».

- «Добавить» — код + необязательная подпись; занятый код (409 `STORAGE_CELL_EXISTS`) даёт понятный
  текст под полем.
- «Создать сетку» — лист «Создать сетку ячеек»: «Стеллажи» (`A-C`, `А-Г`, `1-5` или `A, B, C`),
  «Полок в стеллаже», «Ячеек на полке», разделитель (`-`, `.`, `/`, «Слитно»), «Ведущие нули».
  Предпросмотр «Будет создано: 60» и первые коды считают функции `shared/utils/storageCells`
  (те же, что примет сервер); больше 2000 — кнопка заблокирована с пояснением; уже существующие
  коды в счётчик не входят. Отправка — `bulkCreate`, итог «Создано N. Уже были: …».
- Тап по ячейке → «Склад» с фильтром по ней: чип «Ячейка A-01-03 ×» над списком, крестик снимает.
- Долгое нажатие или «⋯» в строке (только `warehouse_manage`): «Товары в ячейке», «Переименовать»,
  «Удалить».
- Удаление пустой ячейки — диалог подтверждения. Непустой — алерт «Ячейка A-1-2 не пуста»:
  «Перенести N товаров» (открывается тот же пикер, без «Без адреса» и без удаляемой ячейки →
  `remove(id, { moveTo })`), «Открепить» (`remove(id, { detach: true })`, `haptic('warning')`),
  «Отмена». Если пока смотрели экран, в «пустую» ячейку положили товар, сервер вернёт
  `STORAGE_CELL_NOT_EMPTY` + `productsCount`, и вопрос задаётся заново.
- Роли: читать — `warehouse_access` (или `warehouse_manage`), менять — `warehouse_manage`. Без
  права экран показывает «Недостаточно прав». Ошибка загрузки / сети — «Не удалось загрузить ·
  Повторить», не сломанный список.

### Склад (`ProductsScreen`)

- Строка: чип кода в метастроке после цены, перед вторым слотом (себестоимость / папка).
- Поиск: сервер `?search=` уже находит по коду ячейки; проекция списка отдаёт код в строку.
- Форма создания и правки: поле «Ячейка хранения» после «Остаток | Мин.» — есть всегда, тап →
  пикер, который рендерится ВНУТРИ модалки формы (сиблинг-Modal поверх открытой модалки на iOS
  Fabric не презентуется — тот же приём, что у сканера штрихкода). В payload адрес уходит при
  создании только если выбран, при правке — только если изменён (`null` снимает адрес).
- Фильтр «ячейка X»: клиентский, по уже загруженному списку (склад отдаётся целиком одной
  страницей); ключ запроса товаров не меняется. Работает как плоский список без папок, поэтому
  папка у строки видна. Смена склада в переключателе фильтр гасит: ячейка принадлежит одному складу.
  Если каталог больше лимита списка, баннер «Показаны N из M» честно говорит, что в ячейке могут
  быть не все товары, и подсказывает поиск по коду.

### Карточка товара (`ProductDetailScreen`)

- Просмотр: первая строка блока «Информация» — «Ячейка хранения» (код моноширинно, «Не указана»).
  Тап (только `warehouse_manage`) → пикер, выбор сохраняется сразу отдельным PATCH `{ storageCellId }`.
- Правка (инлайн-форма): поле «Ячейка хранения» после «Остаток | Мин.»; уходит вместе с формой
  и только если менялось, чтобы форма не затирала адрес, выставленный с другого экрана.
- Пикер показывает только ячейки склада ТОГО товара. Ответ `PATCH` может прийти без склейки с
  ячейкой (в спеке склейка гарантирована для чтения, не для записи), поэтому карточка дописывает
  выбранную ячейку (`withRequestedStorageCell`) и тут же перечитывается с сервера.

### Подбор в Кассе и инвентаризация

`ProductPickerScreen`: код ячейки в строке рядом с ценой; клиентский поиск ищет и по коду
(регистр и пробелы не важны — `cellCodeMatchesQuery` по правилу `normalizeCellCode`).
`InventoryScreen`: код в строке под названием рядом с категорией, поиск «Поиск товара или ячейки…».
Оба экрана получают код ячейки из полного ответа товара, отдельных запросов нет.

## Fallback и совместимость

- У компании нет ячеек: чип не рисуется (строка склада, подбор и инвентаризация — как раньше),
  поиск и кэш прежние. Поле «Ячейка хранения» в форме и карточке есть всегда — по требованию
  продукта — и ведёт в «+ Создать ячейку»; в карточке оно показывает «Не указана».
- Бэкенд без модуля ячеек (старый прод): `?fields=` тихо отбрасывает неизвестные ключи, поэтому
  список склада работает как прежде; экран и пикер показывают «Не удалось загрузить · Повторить»,
  создание сообщает причину отказа сервера. Поле адреса в payload не уходит, пока его не выбрали.
- Кэш старой версии приложения без ячеек: ключ `['storage-cells']` в нём отсутствует, товары
  из кэша без `storageCell*` просто без чипа; после первого обновления списка чип появится.
- Android: общий RN-код без iOS-only API; mono-шрифт через `Platform.select`, ячейки на экране
  и в пикере — обычные RN-компоненты и FlashList. Native-модули и `app.json` не тронуты,
  `expo prebuild` не нужен.
- `shared/` и backend в этой задаче не менялись.

## Как владельцу проверить на iPhone

1. Склад → кнопка ⇄ в шапке → «Ячейки хранения» → «Создать сетку»: стеллажи `A-C`, полок `3`, ячеек `4`,
   разделитель «-». Предпросмотр «Будет создано: 36», коды `A-1-1 … C-3-4`. «Создать» → «Создано:
   36 ячеек», в списке 36 строк «Пусто». Баг: счётчик расходится с итогом, при 2001+ ячеек кнопка
   активна, вылет при вводе `9999` в «Полок».
2. Склад → карточка любого товара → «Изменить» → «Ячейка хранения» → выбрать `A-1-2` → «Сохранить».
   В списке склада у товара справа от цены плашка `A-1-2`; в списке ячеек у `A-1-2` — «1 товар».
   Баг: плашка сдвигает цену или остаток, высота строки выросла, счётчик не обновился.
3. Склад → строка поиска: ввести `a-1-2` (любой регистр, с пробелами) — находится товар. То же в
   Кассе → подбор товара, и в Инвентаризации. Баг: не находит по строчным буквам.
4. «Ячейки хранения» → долгое нажатие на `A-1-2` → «Удалить» → алерт «не пуста»: «Перенести 1
   товар» → выбрать `A-1-3` → товар теперь в `A-1-3`, ячейки `A-1-2` нет. Повторить с «Открепить»:
   товар остался на складе без плашки. Баг: товар пропал, «Перенести» предлагает саму удаляемую
   ячейку, удаление пустой ячейки идёт без подтверждения.
5. Касса → подбор товара: у товара с адресом виден код рядом с ценой и остатком, у товара без
   адреса строка прежняя; на самом узком iPhone (SE / mini) цена и остаток не съезжают.
6. Компания без ячеек (или склад «Брак» / «Б/У», где их не заводили): список склада и подбор в
   Кассе выглядят как раньше, в форме товара «Ячейка хранения: Не указана», её пикер открывается
   с текстом «На этом складе пока нет ячеек» и кнопкой «+ Создать ячейку». Баг: пустой блок, отступ, лишний
   спиннер или «Не удалось загрузить» там, где бэкенд отвечает 200.

## Проверки

`cd mobile && npm run typecheck && npm run lint && npx jest` — зелёные (52 suites / 931 тест,
включая `plateMask.test.ts`, `storageCells.test.ts`, `storageCellsUi.test.ts`,
`persistentCache.storageCells.test.ts`; `npm run typecheck` в `pretypecheck` гонит ещё 10
критичных suites).

Ограничения среды: iOS Simulator, физический iPhone и Android-эмулятор не запускались (владелец
просил не тратить на них лимиты), `expo prebuild` / `pod install` / Xcode не нужны — native не
менялся. Экраны проверены типами, линтером и юнит-тестами чистой логики (коды сетки, поиск,
разбор ошибок, склейка адреса, whitelist кэша); вёрстку, жесты (долгое нажатие, цепочки Modal на
iOS Fabric) и работу против настоящего backend с модулем ячеек предстоит подтвердить чек-листом
выше.
