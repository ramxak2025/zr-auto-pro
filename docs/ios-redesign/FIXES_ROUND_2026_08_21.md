# Раунд правок 2026-08-21: инвентаризация, склад, записи, поставщики

Четыре точечные правки из августовского списка владельца (пункты 1–4).
Крупный пункт 5 (кассовая смена v2) — отдельно: `CASH_SHIFT_V2_SAFE_2026_08_21.md`.

## 1. Инвентаризация — кривой экран (P0)

**Проблема (скриншот IMG_6769):** чипы категорий растянуты гигантскими капсулами
на пол-экрана, список товаров не виден — провести инвентаризацию невозможно.

**Причина:** у горизонтального `ScrollView` чипов в `InventoryScreen.tsx` не был
переопределён дефолт RN `flexGrow: 1` — в колонке он конкурировал за высоту с
FlashList и забирал пол-экрана, а чипы растягивались по кросс-оси.

**Фикс:** `catScroll: { flexGrow: 0, flexShrink: 0 }` + `alignItems: 'center'`
на contentContainer (эталон — все соседние экраны с чипами). Backend «Провести»
был исправен и не менялся.

## 2. Склад — массовое перемещение + перенос папок

- В режиме выделения рядом с «Удалить (N)» появилась кнопка **«Переместить (N)»**
  (гейт `warehouse_manage`) → выбор папки → новый транзакционный
  `POST /products/bulk-move` (скоуп по складу, ≤2000 товаров, папка-цель
  создаётся идемпотентно, '' = корень).
- **Перенос папки**: лонг-пресс по папке → «Переместить папку» (работает и для
  производных path-only папок — материализуются перед переносом). Механизм —
  существующий `PATCH /warehouse/categories/:id/rename`, который ужесточён:
  warehouse-скоуп всех UPDATE (одноимённые пути в Б/У/браке больше не задеваются),
  запрет переноса папки в собственное поддерево (400), проверка коллизии имён
  (400 вместо 500), нормализация пути. Вложенность папок остаётся path-моделью
  («А/Б/В») — `parent_id` не вводился сознательно.
- `FolderPickerModal` обобщён (subtitle / confirmLabel / excludePrefix) с полной
  обратной совместимостью одиночного переноса.

## 4. Поставщики — таб-бар, корректировка, пометка удаления

- **Таб-бар:** `SupplierDetailScreen` переведён на `useTabBarScrollInsets` —
  последняя поставка больше не прячется под плавающим баром (iOS inset +
  Android padding).
- **Корректировка поставки:** `PATCH /suppliers/deliveries/:id` (гейт
  `suppliers_manage`) — одна транзакция (локи: поставка → товары по id →
  поставщик): дельты количеств двигают остатки **корректирующими
  stock_movements** (видны в журнале), долг поставщику — дельтой суммы;
  оплаченная поставка с несторнированным авто-платежом → 400 («сначала сторно»);
  нехватка остатка (товар уже продан) → 400 без клампа; у поставок «по заказу»
  синхронизируется `received_quantity`; `cost_price` сознательно не трогается.
  UI — кнопка «Изменить» в раскрытой карточке, модал строк qty/price.
- **Удаление = пометка:** `DELETE /suppliers/deliveries/:id` — soft-delete
  (миграция `154`): откат остатков и долга + `deleted_at/deleted_by/причина`.
  Поставка остаётся в списке с бейджем «Удалена» и зачёркнутой суммой (паттерн
  сторно-платежа), на mobile и web.
