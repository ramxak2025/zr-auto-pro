# Госномер — спецификация ввода и поиска

## Российский номер

### Формат
- 1 буква + 3 цифры + 2 буквы + 2-3 цифры региона
- Пример: `Р332РА05`
- Хранение в БД: 8 или 9 символов без пробелов, кириллица заглавная

### Разрешённые буквы (ГОСТ Р 50577-93)
`А, В, Е, К, М, Н, О, Р, С, Т, У, Х`

### Латиница → Кириллица (auto-normalize)

| Латиница | Кириллица |
|----------|-----------|
| A | А |
| B | В |
| E | Е |
| K | К |
| M | М |
| H | Н |
| O | О |
| P | Р |
| C | С |
| T | Т |
| Y | У |
| X | Х |

Любая другая буква — отбрасывается.

### Визуальное отображение

Хранится: `А123АА77` (8 символов)
Показывается как **два визуальных блока**:

```
┌─────────────────────┬───────────┐
│   А  123  АА        │  77       │
│                     │  ▆▆▆ RUS  │
└─────────────────────┴───────────┘
        main                region
```

**Регион никогда не дублируется в main-блоке.**

Неправильно:
```
┌─────────────────────┬───────────┐
│   А  123  АА  77    │  77       │  ❌
└─────────────────────┴───────────┘
```

Правильно:
```
┌─────────────────────┬───────────┐
│   А  123  АА        │  77       │  ✅
└─────────────────────┴───────────┘
```

Это уже корректно реализовано в `RussianPlateInput.tsx` — `splitPlate()` режет clean-string на main (0..6) и region (6..9), и каждый отрисовывается в своём контейнере.

### Логика ввода

1. Пользователь вводит символ → `processPlateInput(raw)` нормализует:
   - `toUpperCase()`
   - `LAT_TO_CYR[ch] || ch`
   - проверяет по позиции (0=letter, 1-3=digit, 4-5=letter, 6-8=digit)
   - отбрасывает невалидные символы
2. Пользователь видит отформатированную строку с пробелами: `А 123 АА 77`
3. Под капотом сохраняется чистая строка: `А123АА77`
4. Backspace удаляет 1 символ из конца чистой строки и пересчитывает display

### Валидация

`isValidPlate(clean)` — `^[АВЕКМНОРСТУХ]\d{3}[АВЕКМНОРСТУХ]{2}\d{2,3}$`

Применяется только если пользователь хочет финальную проверку (например, при сохранении). Для UI индикации не используется — мы не помечаем неполный ввод красным.

## Иностранный номер

### Формат
- Свободный латиницей + цифры
- Длина 4-15 символов
- Пример: `BG3845PA`, `T-123-AB`, `1234-AB-5`

### Логика ввода
- Без cyrillic-нормализации
- `autoCapitalize="characters"` — приводим к верхнему регистру
- Разрешено: `[A-Z0-9 \-/]`
- Длина до 15 символов

### Визуальное отображение
Простая полоска с синим INT-маркером слева:

```
┌──────┬──────────────────────┐
│ INT  │   BG 3845 PA         │
└──────┴──────────────────────┘
```

## Переключение режимов

### Текущая проблема

Сейчас режим определяется автоматически по первому символу через `isRussianInput()`:
- Если первый символ — кириллическая буква из `АВЕКМНОРСТУХ` или эквивалент латиницей (A, B, E, K, M, H, O, P, C, T, Y, X) → RU mode
- Иначе → foreign mode

Проблемы:
1. Пользователь не понимает, что произошло переключение
2. Если он ошибся — нельзя переключиться обратно без очистки поля
3. Цифра в начале → foreign-mode залипает, RU-нормализация дальше не работает

### Решение — явный переключатель

Над input — `PlateModeSwitcher` (segmented control), 2 опции:
- 🇷🇺 RU
- 🌐 INT

Контроллируется родительским экраном, привязан к state переменной `plateMode: 'ru' | 'foreign'`.

Поведение:
- Дефолт: `plateMode = 'ru'` (большинство клиентов российские)
- Тап на RU → принудительно использовать RU маску, прогнать текущий value через `processPlateInput`
- Тап на INT → принудительно foreign, value = `value.toUpperCase().replace(/\s+/g, ' ')`
- При смене режима поле НЕ очищается — пользователь сохраняет ввод

## Поиск клиента

### Backend контракт

`GET /clients?search=<query>` — backend ищет по нормализованной строке.

### Клиентская нормализация перед отправкой

Новая функция `normalizePlateForSearch(raw, mode)`:

```ts
function normalizePlateForSearch(raw: string, mode: 'ru' | 'foreign'): string {
  if (!raw) return '';
  if (mode === 'ru') {
    // Apply RU mask: latin→cyrillic, uppercase, only valid chars
    return processPlateInput(raw.replace(/\s/g, ''));
  }
  // Foreign: just uppercase, trim
  return raw.replace(/\s+/g, ' ').trim().toUpperCase();
}
```

Перед отправкой в `clientsApi.getAll({ search })`:
```ts
const normalized = normalizePlateForSearch(plateSearch, plateMode);
```

### Pagination и debounce

- React Query уже дебоансит через staleTime
- Дополнительно — `enabled: normalized.length >= 2` (поисковая строка ≥ 2 символов)
- `keepPreviousData: true` — при наборе следующего символа предыдущий результат остаётся виден до загрузки нового

### Отображение результата

- Подбираются клиенты, у которых:
  - `client.cars[].plateNumber` содержит `normalized`, ИЛИ
  - `client.fullName` содержит query (как есть, не нормализованный — для поиска по ФИО)
- Показываем до 5 результатов в inline-списке с plate-chip, makeModel, fullName

### Состояние «не найдено»

- Показываем `Клиент не найден` ТОЛЬКО когда:
  - `normalized.length >= 2`
  - И `query` уже завершился (`!isFetching`)
  - И `results.length === 0`
- Никогда при пустом или коротком вводе — там показываем дефолт «Розничный покупатель»

Сценарии:
- `processPlateInput('p332pa05')` → `'Р332РА05'`
- `processPlateInput('А 123 АА 77')` → `'А123АА77'`

- `splitPlate('А123АА777')` → `{ main: 'А123АА', region: '777' }`

- `isValidPlate('А123АА7')` → `false`

- `normalizePlateForSearch('bg3845pa', 'foreign')` → `'BG3845PA'`
