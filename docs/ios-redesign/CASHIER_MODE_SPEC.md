# Режим «Кассир» — спецификация (Round 14, 2026-08-03)

По надиктованному видению владельца (2026-08-02, две сессии). Главные приоритеты: **надёжность денег** (не теряются, не умножаются, не вычитаются) и **удобство**.

## Что уже есть (волна 092 — переиспользуем)

Тумблер `tenants.shift_mode_enabled` («Режим кассовой смены» в настройках компании), право `accept_payment` (ячейка матрицы «Кассир смены»), серверные гейты: не-кассир создаёт только отложенный заказ-наряд (деньги = 0, склад не списывается), закрыть оплатой может только кассир (403). Доска work_board_columns + work_status, авто-СМС «машина готова» при переходе в колонку с notify_client. Центральная кнопка таб-бара уже динамическая (у мастера в режиме — Доска вместо Кассы).

## Конвейер (флоу владельца)

**Принят → В работе → Готова → Оплачена → Выдана (закрыт)** (+ «Отменён» с причиной)

1. **Администратор**: клиент/авто как в обычной Кассе → работы/товары (можно частично, можно пусто) → **комментарий мастеру** («что сделать») → **выбор исполнителей (одного или нескольких)** → при желании **место** («возле задних ворот») → заказ падает на доски всех исполнителей.
2. **Мастер**: kanban-доска своих машин (карточка: авто+госномер, клиент, место, комментарий админа). Открывает заказ — дополняет/меняет **только если роль разрешает** (новая ячейка матрицы «мастер меняет назначенный заказ»; выключена — только выполняет). Готово → двигает в «Готова».
3. **Кассир** (отдельная строгая роль-пресет): свой экран — очередь «Готовых» + поиск по госномеру. Видит весь заказ и сумму → принимает оплату (нал/карта/смешанная), **может дать скидку** → «Оплачено».
4. **Мастер** видит «Оплачена — можно выдавать» → выдал → «Выдана» → заказ закрыт, уходит в Журнал.
5. **Владелец/администратор**: вся картина (все доски, фильтр по мастерам) + Движение денег как сейчас.

## Роли и права

- **«Кассир» — роль-пресет** (создаётся в один тап из раздела Роли): `accept_payment`=да, видит все чеки, кассовые смены, клиенты (просмотр); остальное закрыто. НЕ новый system_key (не трогаем cutover-механику) — обычная тенантная роль из шаблона.
- **Совмещение запрещено продуктом**: кассирский пресет не содержит прав мастера/админа; предупреждение в редакторе ролей при попытке добавить кассиру исполнительские права (мягкое, не блокирующее — владелец в своём праве).
- Новая ячейка матрицы: **«Изменяет назначенный заказ» (мастер)** — можно/нельзя дополнять чек.

## Деньги (инварианты)

- До «Оплачено» заказ = отложенный чек: **ни выручки, ни движения денег, ни списания склада, ни зарплат** (существующий механизм is_deferred).
- «Оплачено» = единственная точка рождения денег: кассир выбирает способ (нал/карта/смешанная, суммы), применяет скидку → активация чека тем же серверным путём, что обычное закрытие (все пересчёты/гейты сохранены).
- «Выдана» без «Оплачена» — невозможна (UI + серверный гард).
- Смена режима (вкл/выкл) блокируется при наличии незакрытых заказ-нарядов — с показом списка, что закрыть.

## Новое в данных

- `check_assignees` (миграция): несколько исполнителей на заказ; зарплатная атрибуция НЕ меняется (по строкам, как сейчас).
- `tenant_locations` (миграция) + `checks.location_id`: справочник мест в настройках, место на карточке доски, фильтр.
- Статусы = колонки доски (существующие work_board_columns) + системные вехи paid/delivered поверх.

## Таб-бар по ролям (без правок Swift)

Native-бар уже принимает `tabCount` и любые иконки из JS. `TabBarShared` становится функцией роли+режима:

- **Мастер**: Главная · Склад · **Доска** (центр) · Журнал · Ещё (как сейчас в orderMode).
- **Кассир**: Главная · Смены · **Касса-оплата** (центр, очередь готовых) · Журнал · Ещё.
- **Админ/владелец**: Главная · Склад · **Приёмка** (центр — создание заказа) · Доска · Ещё (Журнал внутри).
- Режим выключен → всё байт-в-байт как сейчас.

## Уведомления

Push по цепочке: назначение → исполнителям; «Готова» → кассирам; «Оплачена» → исполнителям. «Машина готова» клиенту — существующий маркетинг-механизм (колонка с notify_client).

## Ограничения v1 (честно)

- Кассирский экран — mobile-first; web получает паритет через существующие WorkBoardPage/CheckDetailPage + приём оплаты.
- Отмена заказа — статус с причиной, без частичных оплат (не бывает денег до «Оплачено»).
- Пересменка/инкассация — существующий модуль кассовых смен, в v1 не переделывается.
