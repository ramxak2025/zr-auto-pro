# Backend обмена 1С:УНФ 3 — пилот, 2026-10-03

Пилот дополняет кабинет владельца и транспорт `integrations/one-c/bridge.mjs`.
Работа с настоящей информационной базой 1С **не проверена**. Адаптер метаданных
и проведения документов УНФ в репозитории отсутствует. Подключение и все
направления по умолчанию выключены; выпуск приложения не включает обмен.

## Доступ и хранение

- Миграция `174_one_c_exchange.sql`: подключение, сопоставления, журнал событий;
  уникальные идентификаторы событий и сопоставлений; принудительная tenant RLS.
- Одно подключение на автосервис с одним выбранным действующим филиалом.
  После появления истории филиал менять нельзя.
- Создать подключение может действующий владелец (`director`) внутри своего
  автосервиса. Ключ показывается только при создании/замене; в БД SHA-256 и
  последние шесть символов. Замена немедленно отзывает прежний ключ.
- Bridge guard проверяет ключ, активность владельца, принадлежность и активность
  филиала. Устанавливает `req.user.tenantID/currentPointId` до существующего
  `TenantContextInterceptor`; действуют обычный контекст RLS и подписка.
- Включение `active` без `mappingConfirmed=true` отвергается самим API.
  Снятие подтверждения требует одновременной паузы. При отсутствии подтверждения
  импорт остатков и оплат принудительно выключен.

## HTTP-контракт

Общий клиент: `shared/api/oneC.ts`, `createOneCApi(api)`.

| Метод/путь                                            | Назначение                                           |
| ----------------------------------------------------- | ---------------------------------------------------- |
| `GET /one-c/connection`                               | `{connection, availablePoints, pilotNotice}`         |
| `POST /one-c/connection`                              | `{pointId}` → `{connection, apiKey}`                 |
| `PATCH /one-c/connection`                             | `{pointId?,status?,mappingConfirmed?,capabilities?}` |
| `POST /one-c/connection/rotate-key`                   | Новый одноразово показанный ключ                     |
| `GET /one-c/journal?limit=&offset=`                   | `{items,total}`, только текущий автосервис           |
| `GET /one-c/bridge/export?entityType=&cursor=&limit=` | `{items,nextCursor}`                                 |
| `POST /one-c/bridge/import`                           | Одно неизменяемое событие                            |
| `POST /one-c/bridge/ack`                              | Подтверждение отправленных версий                    |

Owner API использует JWT. Bridge API использует `Authorization: Bearer ax1c_…`.
Tenant и филиал bridge берёт исключительно из подключения, не из payload.
`capabilities` содержит флаги `import/export` для всех шести типов.

Событие импорта:
`{eventId,entityType,externalId,baseRevision?,payload}`.
Повтор того же события возвращает сохранённый результат; иное тело с прежним
`eventId` — `409`. При конкуренции за один исходный объект — `409`, разрешён
повтор **того же** события после завершения текущей обработки.

Экспорт: `{autexaId,externalId,revision,payload}`. `revision` — SHA-256
канонического нормализованного payload. `nextCursor` относится к просмотренным
строкам; страница может иметь пустой `items` и непустой курсор. Такой курсор
нужно продолжить. Неизменившиеся подтверждённые снимки не отправляются снова.
ACK: `{entityType,items:[{autexaId,externalId,revision}]}` →
`{accepted,needsReview}`. Проверка актуальной версии и сопоставление выполняются
в транзакции под блокировкой строки. Чужой объект, новая локальная правка или
коллизия идентификаторов дают запись для сверки, не молчаливую перезапись.

## Поддержанные изменения

| Тип          | Экспорт                                                                            | Импорт                                                                          |
| ------------ | ---------------------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| `products`   | Название, категория, штрихкод, единица, цены, минимальный остаток, склад, удаление | Создание с нулевым остатком; изменение описания/цен/категории по `baseRevision` |
| `clients`    | Имя, телефон, комментарий                                                          | Создание и изменение по `baseRevision`                                          |
| `stock`      | Снимок `{productId,warehouseId,quantity}`                                          | Отдельное приходное/расходное движение с ожидаемыми складом и остатком          |
| `purchases`  | Поставщик, состояние, примечание, сумма и строки закупки                           | Создание штатного черновика закупки                                             |
| `workOrders` | Заказ-наряд, строки, сумма, состояние                                              | Создание штатного неоплаченного заказ-наряда                                    |
| `payments`   | Оплата проведённого чека                                                           | Точное закрытие неоплаченного заказ-наряда наличными, картой или смешанно       |

Продукты и остатки ограничены складами выбранного филиала, документы — самим
филиалом. Общие клиенты с `point_id=NULL` доступны внутри своего автосервиса;
клиенты другого конкретного филиала не выдаются.

Карточки товара/клиента изменяются через родные сервисы с переданной
транзакцией. Сначала `SELECT … FOR UPDATE`, сравнение версии, затем штатное
изменение. История цен записывается в той же транзакции. Категория — строковый
путь до 500 символов, как в обычном API. Произвольные поля запрещены.

Payload движения остатка:

```json
{
  "productId": "UUID товара Autexa",
  "type": "expense",
  "quantity": 2.5,
  "expectedStock": 5,
  "expectedWarehouseId": "UUID склада Autexa",
  "reason": "Обмен 1С"
}
```

`type` — только `income`/`expense`, количество положительное, до трёх десятичных
знаков. `externalId` идентифицирует **одно движение** исходной системы. Другое
движение получает другой ID; правка уже сопоставленного движения требует
ручной сверки. Склад и остаток проверяются под блокировкой родного
`ProductsService.updateStock`; недостаточный остаток отвергается до обрезания
значения до нуля. Импорт не создаёт произвольный денежный расход. Экспортный
ACK остатка относится к снимку и не использует сопоставления входящих движений.

Оплата проверяет итоговую сумму и статус непосредственно под блокировкой
чека. Она не может изменить уже проведённую оплату при конкурентном закрытии.
Возвраты, рассрочки, платежи поставщикам, проведение/редактирование истории
закупок и автоматическое удаление не входят в пилот.

## Неизвестный исход и сверка

`processing` сохраняется до вызова родного доменного сервиса. Если процесс
оборвался после доменного commit, повторное событие переводится в
`needs_review` и не исполняется снова. Новый `eventId` для того же ещё не
сопоставленного объекта также не обходит незавершённую операцию. Блокировка
исходного объекта удерживается выделенной сессией PostgreSQL; соединение
с ошибкой снятия блокировки уничтожается, не возвращается в пул.

Общей транзакции между всеми существующими доменными сервисами и журналом
обмена нет. Поэтому `needs_review` означает обязательную сверку, а не обещание
отката. Автоматического разрешения таких конфликтов в пилоте нет. В журнал не
пишутся ключи или полный payload с персональными данными.
