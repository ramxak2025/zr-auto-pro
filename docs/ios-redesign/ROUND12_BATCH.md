# Round 12 — ночной батч 2026-07-27 (v3.2.0)

9 пунктов владельца, реализованы автономно за ночь. Ветка `feat/round12-batch` → `refactor/full-audit-2026`.

## 1. Журнал чеков: мерцание, исчезающие блоки, фильтры

**Проблема.** «Иногда лагает, чеки целыми блоками мерцают/исчезают, фильтр работает плохо».

**Корень (подтверждён кодом).** Курсор keyset-пагинации строился через `Date.toISOString()` — node-pg отдаёт timestamptz с миллисекундной точностью, БД хранит микросекунды. Усечённый курсор в предикате `(date, created_at, id) < (...)` выкидывал все строки «усечённого окна» — пачки чеков одной транзакции (одинаковый `now()`) выпадали целым блоком на границе страницы. Плюс: COUNT(\*) на каждой странице × поллинг 30с × все загруженные страницы; клиентский (не серверный) фильтр возвратов; blank-cells FlatList на быстром скролле; отсутствие сброса скролла при смене фильтра.

**Решение.** Курсор из сырых pg-text значений (`::text` в SELECT) — микросекунды целы, старые курсоры совместимы. COUNT только на первой странице. Серверные: `isReturned`, поиск по номеру чека, `masterId` учитывает исполнителей строк. Mobile: серверный фильтр возвратов (слот 6 queryKey, позиции 0–4 нетронуты), scroll-to-top при смене фильтров, windowSize 21 + `updateCellsBatchingPeriod`, поллинг только на глубине ≤3 страниц, чипы активных фильтров, filter-aware empty state.

**Дизайн-проход (отдельная просьба владельца).** Карточка чека: клиент/сумма первичны (15/17pt, tabular-nums), статусы только у исключительных чеков, цветная полоса — информация, а не декор. Панель фильтров — сгруппированный «лоток» (ПЕРИОД / СОТРУДНИК / ПОКАЗАТЬ ТОЛЬКО). Сегменты над поиском, честные placeholder'ы. Поиск на вкладке документов был мёртвым контролом — теперь фильтрует. Хаптика select, Reduce Motion не нарушен, BlurView в строках нет.

## 2. Госномер: перестановка цифр (х807кс → Х870)

**Корень.** Контролируемый `selection`-проп на Fabric: коммит устаревшей позиции каретки от кейстрока N долетал после набора N+1 → следующий символ вставлялся не туда. Маска порядко-сохранна и невиновна.

**Решение.** Контролируемый caret удалён целиком (state, проп, хендлеры). Буфер, echo-ring, авто-переход в регион — не тронуты. Правило в `LICENSE_PLATE_FIX.md`: caret руками — только императивно, не через state-проп. Приёмка — быстрый набор на физическом iPhone (гонка timing-зависимая).

## 3. Клиент без телефона

Backend был готов (phone='' легален, дедуп/поиск не ломаются). Сняты два клиентских блокера (QuickClientCreateSheet, web `required`); везде — confirm «Создать клиента без номера телефона? Его нельзя будет найти поиском по номеру» (и отдельный текст при стирании существующего номера). В списках — серое «Без номера» (кроме розничного). Молчаливый проход пустого телефона в ClientsScreen закрыт confirm'ом.

## 4. Права: role-only, тумблеры удалены

**Корень «прав, которые не работают».** Тумблеры «Видимость разделов/подразделов» писали в таблицы 071/073, которые `/auth/me` никогда не возвращал — у сотрудников ничего не менялось. Система уже была на 80% role-only (cutover мигр. 126).

**Решение.** Тумблеры вырезаны по вертикали: backend-роуты+DTO, shared-типы/методы, UI-блоки UsersScreen (вместо них — переход в Роли), двойной гейт MoreScreen. Меню — строго по матрице роли. База знаний/Шаблоны → `knowledge_view`; **Рассрочка → `cashflow_view` (единственное реальное сужение — раньше видели все)**. Таблицы 071/073 остаются в БД до следующего релиза (откат-безопасность). Инварианты целы: «Директор» read-only полные права, `checks.view='own'` у мастера, персональные роли.

## 5. Чек → карточка товара

Тап по товарной строке чека открывает полную складскую карточку (push в свой стек, таб-бар жив), а не модалку движений; история движений — внутри карточки. Params карточки толерантны (`productId` без полного объекта), удалённый товар — честное состояние «Товар удалён со склада» вместо краша. Web: клик по строке → склад с открытой карточкой.

Инфраструктура была на 70% (колонка+индексы, DTO, BarcodeScanner, expo-camera в бинарнике — native rebuild не нужен). ## 7. Розничный confirm

При пробитии без клиента — «Возможно, вы забыли добавить клиента» → Вернуться / Пробить (mobile Alert + web Modal). Не мешает: редактированию, отложенным, заказ-нарядам, явно выбранному розничному. СБП-инвариант: вопрос ДО приёма денег, после оплаты никаких блокировок. Цепочка с овершелл-confirm сохранена.

## 8. Маркетинг: видимые гарантии

**Корень страхов.** Гарантии уже были на сервере (единый гейт guardAndLogSend: потолок 3 сообщения клиенту/24ч поперёк всех типов, дедуп на сущность, окно точного дубля 1ч, race-safe claim), но невидимы: журнал sent_messages никем не читался, дефолты авто-отзыва и booking-уведомлений были ON, заглушки sms/email отвечали фантомным success.

**Решение.** `GET /marketing/sent-messages` (курсорный журнал, telegram помечен «в чат владельца») + экран «Журнал отправок» (mobile+web), `POST broadcast/preview` («Уйдёт N клиентам» до отправки), реестр всех 6 авто-сценариев с тумблерами/триггерами/последней отправкой, включение отзыва показывает реальный шаблон. Лимиты отдаются сервером и видны в UI. Миграция 141: DEFAULT false для новых тенантов, БЕЗ backfill (работающие рассылки не выключены). Заглушки честно падают и исключены из выбора канала. guardAndLogSend не тронут. Подробно: `MARKETING_REDESIGN_V2.md`.
