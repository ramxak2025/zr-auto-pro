# Round 13 — рассрочки (2026-07-30, v3.2.1)

9 пунктов владельца по функционалу рассрочек. Ветка `feat/round13-installments` → `refactor/full-audit-2026`.

## Баги

**1. «Скидка не применяется при рассрочке».** Разведка доказала: контур рассрочки скидку НЕ теряет — план честно копирует итог чека. Причина «пропажи» — задокументированная семантика «скидка только на товары»: в чеке с услугами и товарами меньше суммы скидки итог не уменьшался. **Решение владельца (явное): семантику сохранить.** Фикс — честность UI: Касса (mobile+web) предупреждает «Скидка применена частично: N ₽ из M ₽» / «Скидка не применена: в чеке нет товаров»; web-summary показывает применённую скидку.

**2. Бейдж «installment» в журнале.** 4 мобильных экрана держали локальные словари оплат без ключа рассрочки — переведены на канонический `shared/utils/formatters.paymentMethodLabels`; синий бейдж, иконка календаря в деталке.

**3. «Остаток» обрезался сверху.** Класс бага «631К ₽»: крупная цифра без явного lineHeight наследует body 22. Фикс — lineHeight 38 (hero) + явные высоты у остальных крупных цифр.

## Карточка рассрочки (редизайн)

- **Клиент и авто**: имя, телефон, марка + госномер, постоянные кнопки «Позвонить»/«WhatsApp», «Заказ-наряд» → деталка чека.
- **Фото** — общее хранилище с чеком (check-photos): просмотр, добавление, замена, удаление; секции нет, если чек удалён.
- **Поручители** (миграция 142, RLS): имя, кем приходится, телефон + звонок/WA; добавление/удаление под `debts_manage`.
- **Перенос даты с причиной** (миграция 143, RLS): после выбора даты — модалка причины; история переносов «12 авг → 19 авг» в едином таймлайне с платежами. Сдвиги даты при платеже в историю не пишутся.
- **Звонки**: список звонков клиента за период рассрочки с плеером записей (`calls_view`/`calls_listen`); телефония не настроена → секция скрыта. Web v1 без звонков.
- Guard в calls: клиент без телефона → пустой список (был 500 на NULL и утечка ВСЕХ звонков тенанта на '').

## Редактирование чека рассрочки (п.9)

Разблокирован `editClosedCheck` для чеков с планом (право `edit_closed_check`): клиентские ноги игнорируются, первый взнос неизменен, план пересчитывается в той же транзакции: `paid = взнос + Σпогашений`, `remaining = max(0, итог − paid)`, закрытие/реоткрытие статуса. Смена способа оплаты остаётся 400 в обе стороны; плоский PATCH/activateDeferred/softDelete — прежние запреты.

**Adversarial-ревью (3 линзы, 8 находок → 3 дефекта закрыты до коммита):**

1. Должник плана следует за клиентом чека (была вечная привязка долга к старому клиенту → СМС не тому человеку).
2. Итог ниже внесённого взноса → 400-отказ «оформите возврат» (был молчаливый ратчет: полученные деньги исчезали из «Движения денег», повторный edit наследовал урезанный взнос).
3. Реоткрытие погашенного плана → новая дата платежа +30 дней (была застарелая дата → мгновенная «просрочка» и риск авто-СМС с датой двухмесячной давности).

Переплата из погашений (итог ≥ взноса, но < внесённого всего) закрывает план с warn «излишек N ₽ вернуть вручную» — теперь warn реально достижим.

## Инварианты (проверены ревью)

- `cash + card + GREATEST(итог − cash − card, 0) = итог` — держится после любого edit; чек и план совпадают копейка в копейку.
- Ledger платежей не переписывается никогда; история цела.
- Лок-порядок чек → строки → план, pay/payoff берут только план — дедлока нет, конкурентное погашение сериализуется.
