# VIN-код автомобиля в мобильном приложении (2026-09-25)

Спека — `docs/specs/2026-09-25-VIN.md` (разделы 4 «Клиенты — поведение» и 5
«Проверки»). Контракт закрыт заранее: `shared/types/index.ts` (секция «VIN (171)»,
`Tenant.vinEnabled`), `shared/api/createServices.ts` (`createVinApi`,
`carsApi.lookupByVin`), `shared/api/types.ts` (`vin` в create/update машины),
`shared/utils/vin.ts` (нормализация, валидация, контрольная цифра, формат).

Затронуто в `mobile/`: `src/hooks/useVinEnabled.ts` (новый), `src/utils/vinUi.ts`
(новый), `src/components/{VinInput,VinText}.tsx` (новые), `PlateModeSwitcher.tsx`,
`DuplicateWarningDialog.tsx`, `QuickClientCreateSheet.tsx`, `ClientCarPickerSheet.tsx`,
`screens/{CompanySettings,CheckCreate,ClientDetail,Clients,Cars,CarDetail}Screen.tsx`,
тесты `src/utils/__tests__/vinUi.test.ts`, `src/hooks/__tests__/useVinEnabled.test.ts`.

## Проблема

Владелец хочет, чтобы к машине можно было добавить VIN, по нему сами
записывались марка и модель, а в Кассе клиент находился по VIN. Опция — на
уровне компании, по умолчанию выключена; пока выключена, ни одного упоминания
VIN в интерфейсе быть не должно. Платный источник расшифровки — по ключу самого
клиента.

## Решение

### Признак опции — `useVinEnabled()`

`mobile/src/hooks/useVinEnabled.ts`. Тот же приём, что у `useTenantTimezone`
(`contexts/TenantTimezoneContext.tsx`): хук ничего не запрашивает сам, а читает
кэши по убыванию свежести —

1. `['vin-settings']` (GET/PATCH `/vin/settings`, ключ `company_manage`) — его пишет
   карточка «Автомобили» в настройках: владелец переключил тумблер и сразу видит
   поле VIN и режим «VIN» в Кассе без перелогина;
2. `['my-company']`, если прогрет;
3. профиль `user.tenant.vinEnabled` из `/auth/login` и `/auth/me` — единственный
   источник у мастера (`/my-company` ему закрыт).

Легаси-payload без поля → `false`. Чистое правило приоритета вынесено в
`resolveVinEnabled` и покрыто тестом.

### `VinInput` — одно поле для всех форм

`mobile/src/components/VinInput.tsx`. Нормализует ввод на лету через
`normalizeVin` (верхний регистр, кириллические двойники → латиница, I/O/Q → 1/0/0,
всё вне алфавита отбрасывается, длина ≤ 17), показывает моноширинно с
группировкой `WMI VDS VIS` (`formatVin`), счётчик «12/17», галочка при 17 валидных
символах, мягкое предупреждение о контрольной цифре для североамериканских VIN
(не блокирует сохранение). При 17 валидных символах — debounce 400 мс →
`vinApi.decode`: поле «Марка и модель» пусто → `makeModel` подставляется молча;
заполнено чем-то другим — чип «По VIN: Kia Rio · Заменить». Подпись под полем:
«Определено по VIN» / «Марка по справочнику, модель допишите» / «Марку по VIN
определить не удалось — заполните вручную». Результаты расшифровки кэшируются по
VIN на сессию. Проп `error` — текст 409 `VIN_DUPLICATE` с именем клиента.

Локальный буфер текста с кольцом собственных эмитов — тот же приём, что в
`RussianPlateInput`: контролируемый `TextInput`, значение которого делает круг
через тяжёлый экран Кассы, на Fabric отстаёт и переставляет буквы.

Вариант `variant="search"` — строка поиска Кассы (высота 56, иконка штрих-кода,
кнопка очистки, без подписей; расшифровка выключена — Касса ищет уже заведённую
машину).

`VinText` — общий моноширинный вывод VIN в карточках и строках (гараж клиента,
список «Авто», пикер машины, выбранное авто в Кассе, деталка авто).

### Где появилось поле VIN (только при включённой опции)

| Форма                                                     | Файл                                      |
| --------------------------------------------------------- | ----------------------------------------- |
| Добавить / редактировать авто в карточке клиента          | `ClientDetailScreen.tsx` → `CarFormModal` |
| Inline-авто при создании клиента (список «Клиенты» → «+») | `ClientsScreen.tsx`                       |
| Быстрое создание клиента из Кассы («Клиент не найден»)    | `QuickClientCreateSheet.tsx`              |

Поле стоит под «Марка и модель». В payload `carsApi.create/update` VIN уходит
только при включённой опции (`vin: string | null`, пустое = очистить); при
выключенной запросы байт-в-байт прежние. Дубликат VIN проверяется ДО создания
клиента (`carsApi.lookupByVin`), чтобы клиент не оставался без машины; 409
`VIN_DUPLICATE` от сервера показывается под полем с именем клиента, а в Кассе
предлагает «Выбрать в чек» владельца. Диалог дубликата по VIN не предлагает «Всё
равно создать» — сервер такой дубликат не примет (`hideCreateAnyway`).

Отдельного редактирования авто на экранах «Авто» и деталке авто нет — там
только вывод VIN (`CarsScreen`, `CarDetailScreen` через route-param `vin`).

### Касса — четвёртый режим поиска «VIN»

`CheckCreateScreen.tsx` + `PlateModeSwitcher.tsx`. `searchMode: 'plate' | 'phone' | 'vin'`;
`isVinMode = vinEnabled && searchMode === 'vin'` — если опцию выключили, пока режим
остался в стейте, экран ведёт себя как поиск по номеру. `PlateModeSwitcher`
получил необязательные `vinActive/onVinSelect`: без них рендерится прежний
трёхсегментный (и двухсегментный у Клиентов/CarPlateField) переключатель
байт-в-байт. С четырьмя сегментами включается режим `dense` (minWidth 56, подпись
11pt, ≈ 245pt суммарно), и переключатель стоит на своей строке ПОД подписью
«ПОИСК ПО VIN» — рядом с подписью четыре сегмента на SE/mini не помещаются.

Поиск — один точный `carsApi.lookupByVin` по 17 валидным символам (debounce
300 мс), ключ `['car-vin-lookup', vin]`; `isPlaceholderData` отсекает результат
предыдущего номера, который подставляет глобальный `placeholderData`. Найдено —
одна строка (номер, марка, владелец, VIN моноширинным); тап подставляет пару
клиент+авто тем же `setClientId/setCarId` путём, что и подсказки по госномеру, а
карточка клиента засевается из ответа lookup'а с `updatedAt: 0` (появляется
сразу, `['client-detail']` тут же перечитывается). Не найдено — «Клиент не найден»
→ «Создать клиента» с уже заполненным VIN (шторка сама расшифровывает его и
подставляет марку). Сетевой сбой — та же ветка «Нет связи — Повторить», что у
номера/телефона. Плашка ГОСТ, маска RU/INT и телефонный режим не тронуты;
`plateMask.test.ts` зелёный.

### Настройки компании → «Автомобили»

`CompanySettingsScreen.tsx` → `VinSettingsSection` (ключ `company_manage`, как у
«Смен»). Тумблер «VIN-код автомобиля» сохраняется сразу (optimistic), после ответа
свежие настройки кладутся в `['vin-settings']`, инвалидируется `['my-company']` и
дёргается `refreshUser()` — флаг во всех источниках сходится. Ниже (только при
включённой опции): «Источник данных» — «Бесплатные справочники» либо провайдер из
`providers` (сервер отдаёт список, клиент ничего не хардкодит); поля провайдера
(секреты — `secureTextEntry`, значение сервер не возвращает: «Ключ сохранён ·
Заменить · Удалить»); ссылка «Где получить ключ» (`site`); «Проверить на VIN…» →
`vinApi.decode` → «Kia Rio · 2015», источник, примечания сервера. Ошибка загрузки
настроек (сервер без модуля VIN, нет сети) — плашка «Повторить», не сломанная
карточка.

### Поиск

`ClientsScreen` (режим клиентов) — плейсхолдер «Имя, телефон, госномер или VIN»;
`CarsScreen` — «Госномер (RU/INT), марка или VIN». Сам поиск по VIN делает сервер
через те же `?search=`.

## Fallback и совместимость

- Опция выключена → все ветки с VIN не монтируются, payload'ы без поля `vin`,
  переключатель Кассы прежний. Ничего не персистится дополнительно
  (`['vin-settings']` в whitelist `persistentCache` не добавлен — данные под
  `company_manage`, а флаг и так приезжает в профиле).
- Android: общие файлы без iOS-only API; моноширинный шрифт через
  `Platform.select` (`Menlo` / `monospace`), клавиатура `ascii-capable` — только на
  iOS. Native-модули не тронуты, prebuild не нужен.
- Контракт: `Car` в `shared/types` пока не объявляет `vin` — на mobile поле читается
  мягко через `carVin()` (`utils/vinUi.ts`, тип `CarWithVin`). Когда backend-engineer
  добавит `vin?: string | null` в `Car`, экраны не меняются.
- Backend без `/vin/*` (сейчас прод): карточка настроек показывает «Не удалось
  загрузить настройки VIN · Повторить», расшифровка в поле отдаёт «Не удалось
  расшифровать VIN — марку и модель заполните вручную», сам VIN при этом
  сохраняется как есть; поиск в Кассе — ветка «Нет связи».

## Как владельцу проверить на iPhone

1. Ещё → Настройки компании → карточка «Автомобили»: тумблер выключен, больше
   ничего про VIN. Включить → появились «Источник данных», «Проверить на VIN…».
   Ввести `XTA219010K0123456`, «Проверить» → «Lada … · 2019», источник. Баг: карточки
   нет, тумблер не сохраняется, при включении ничего не появилось.
2. Касса: под подписью «ПОИСК ПО ГОСНОМЕРУ» — четыре сегмента RU · INT · ТЕЛ · VIN
   в одну строку без обрезки (в том числе на iPhone SE/mini). Тап «VIN» → строка
   «VIN автомобиля», счётчик «n/17», при 17 символах — найденная машина с
   владельцем; тап — карточка клиента с плашкой и VIN под маркой. Неизвестный VIN
   → «Клиент не найден» → «Создать клиента»: в шторке VIN уже заполнен, марка
   подставилась. Баг: сегмент не влезает, RU/INT/ТЕЛ ведут себя иначе, чем раньше,
   поиск по номеру сломан.
3. Клиенты → клиент → «Добавить авто»: поле «VIN» под «Марка и модель». Набрать
   `xta219010k0123456` с русской раскладки — превращается в латиницу и верхний
   регистр, при 17 символах марка/модель заполнились сами и подпись «Определено по
   VIN» (или «Марка по справочнику, модель допишите»). Если марка уже была — чип
   «По VIN: … · Заменить». Сохранить машину с VIN, который уже есть у другого
   клиента — под полем красный текст с именем клиента. Баг: буквы прыгают при
   быстром наборе, подстановка перезаписала введённую вручную марку молча.
4. Авто (Ещё → Авто) и карточка клиента: VIN моноширинным под маркой у машин, где
   он есть. Плейсхолдер поиска клиентов — «Имя, телефон, госномер или VIN».
5. Выключить опцию → поле VIN, сегмент «VIN», строки VIN и плейсхолдеры исчезли,
   Касса выглядит как до обновления.
