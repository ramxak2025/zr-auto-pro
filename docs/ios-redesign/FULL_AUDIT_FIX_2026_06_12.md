# Полный аудит и волна исправлений — 2026-06-12

Ветка: `refactor/full-audit-2026`. Запрос владельца: «приложение должно стать быстрее и надёжнее; найти и вылечить баги; иконки показывают жирный кружок с галочкой вместо аккуратной галочки; расписание открывается через раз; проверить безопасность и логику; без костылей».

Методика: мульти-агентный аудит (7 параллельных аудиторов: иконки, расписание, производительность, баги, безопасность backend, продуктовая логика, native-Swift), каждая серьёзная находка прошла адверсариальную верификацию отдельным агентом-скептиком (1 из 27 находок отклонена как ложная). Затем 3 волны исправлений по непересекающимся зонам файлов (15 агентов).

---

## 1. «Расписание открывается через раз» — корень и лечение

**Корень (P0):** `gated()` в `AppNavigator.tsx` вызывался инлайн в JSX — на каждый ререндер MoreStack создавалась **новая идентичность компонента**, react-navigation размонтировал и заново монтировал ScheduleScreen посреди push-перехода. Видимый симптом — экран «не открылся» или мигнул и закрылся.

**Лечение:**

- Все 9 `gated()`-обёрток подняты в module scope (`GatedSchedule`, `GatedClients`, …) — идентичность стабильна, ремоунтов нет.
- Тяжёлый первый монтаж сетки (~465 Touchable+SVG ячеек синхронно во время перехода) отложен: первый кадр — `GridSkeleton`, реальная сетка после `InteractionManager.runAfterInteractions`.
- Каждая строка дней — **один** row-level `Pressable` (день вычисляется из `locationX / CELL_W`), вместо ~465 экземпляров Touchable.
- Скелетон вместо ложного «Нет мастеров» при загрузке `['users']`; ошибка → строка «Нажмите, чтобы повторить».
- «Сегодня/прогул» считались по UTC (`toISOString`) — после 21:00 МСК день съезжал. Теперь локальная дата.
- Фейковый месяц-степпер на «Смены» заменён честным: backend `GET /schedule/my-stats` получил **опциональные** `dateFrom/dateTo` (контракт аддитивный, web не тронут), вкладка обёрнута на выбранный месяц.
- Владельцы (superadmin/director/owner) убраны и из рейтинга посещаемости (в сетке уже были скрыты); backend `/schedule/today` теперь фильтрует скрытых сотрудников.
- `freezeOnBlur: true` на Tab.Navigator — фоновые табы не ререндерятся.

## 2. «Жирный кружок вместо галочки» — иконки

**Корень:** shim Ionicons→Lucide передавал `fill={color}` всему SVG; lucide-react-native размазывает fill на **каждый** дочерний path. Любой глиф, чей смысл — внутренние штрихи (галочка в круге, крестик в круге, «!» в треугольнике, галочка в щите, клапан конверта), превращался в залитый блоб одного цвета. Вдобавок `CheckCircle` в Lucide — алиас открытой дуги `CircleCheckBig`, при заливке дающей рваный блоб.

**Лечение (ioniconsMap.ts):**

- `checkmark-circle` перенацелен на закрытый `CircleCheck`, `fill` снят — везде читаемое кольцо с галочкой (~30 мест починены одной правкой).
- Систематический аудит **всех** `fill:true` записей по реальной геометрии глифов установленной версии: fill снят у 28 записей (close-circle, alert-circle, warning, shield-checkmark, mail, cube, camera, business, receipt, pie-chart, medkit, document, wallet, card, …), оставлен у 26 настоящих силуэтов (heart, star, flame, folder, play, person, …). Правило зафиксировано комментарием в карте: «fill только для одного замкнутого пути без внутренних штрихов».
- Добавлены отсутствовавшие имена (`checkmark-done`, `refresh-circle`) — раньше рендерились бессмысленным кружком-плейсхолдером.
- Точечные замены семантики: индикаторы выбора в пикерах, paywall-списки и белые галочки на цветных CTA → простая Apple-style `checkmark` (17 мест); статусные бейджи остались круглыми. Мелкие 11–12px кольца увеличены до 13–14.

## 3. Надёжность и баги (mobile)

- **Push (P0):** регистрация токена использовала старый удалённый EAS projectId — теперь читается из `app.json` (`Constants.expoConfig.extra.eas.projectId`). Токен снимается при logout (чужие пуши не приходят). Тап по пушу открывает карточку чека (navigationRef + очередь cold-start).
- **Касса (P0):** математика скидки расходилась с backend/web — скидка применялась и к услугам и допускала отрицательный итог, портя кассовый учёт. Выровнено с серверной семантикой (скидка по товарам, итог ≥ 0), строка «Скидка» показывает реально применённую сумму, подсказка «Скидка применяется к товарам».
- Десятичная запятая больше не обнуляет цену/кол-во; фото-доступ по `sub.features`, а не по имени тарифа; загрузка чека в режиме редактирования через useQuery с ошибкой и retry.
- **Отчёты (P1):** все периоды строились по UTC — в российских поясах диапазоны съезжали на день. Локальный `toLocalISODate` (новый `utils/dates.ts`), также в «Звонки сегодня» и префетче.
- **Офлайн-стратегия (P1):** TanStack `onlineManager` подключён к NetInfo; красный баннер «Нет соединения»; глобальный fallback `mutations.onError` (Alert + haptic) — закрыл ~36 молчаливых мутаций разом; `networkMode:'always'` — офлайн-мутации падают сразу, а не висят вечным спиннером.
- Открыть/закрыть смену, удаление чека, имущество (списание с подтверждением «хранится 7 дней»), инвентаризация (по-позиционный прогресс «N из M», «Повторить незавершённые») — везде честные ошибки и haptics. Pull-to-refresh добавлен на Звонки и Имущество. Выход из аккаунта — с подтверждением.
- **Журнал:** удаление чека инвалидирует все денежные ключи; отложенный чек закрывается в один тап «Принять оплату» (web-parity `isDeferred:false`); фильтр «Отложенные» (новый аддитивный параметр `isDeferred` в `GET /checks`); error-state со «Повторить»; `maxPages:5` ограничил 30-секундный опрос.
- Редактирование услуг/товаров теперь инвалидирует ключи пикеров Кассы (`['all-services']`/`['all-products-check']`) — устаревшие цены не попадают в чек.
- «Клиент не найден» в Кассе больше не тупик: лист «Создать клиента» (ФИО+телефон+номер+марка) с проверкой дублей, двухшаговым create и мгновенным выбором в чек.
- Oversell-защита: жёлтая строка «На складе только N шт» + подтверждение при проведении (не блок — кеш может отставать; для отложенных чеков не спрашивает).

## 4. Производительность

- `persistentCache`: GC при гидрации (битые/просроченные/деперсистнутые записи удаляются батчем), кап вариантов по префиксу (3 месяца расписания/зарплаты, 10 клиентов, 2 страницы журнала), `JSON.stringify` ушёл из горячего пути в debounced flush под `InteractionManager`.
- Поисковые наборы больше не персистятся (positional-ключи Журнала/Поставщиков) и не подсовываются при холодном старте.
- «Клиенты» больше не открываются пустыми: персистится и префетчится реальный ключ `['clients-infinite', …]` (прежний префетч был мёртвым).
- Поиск по номеру в Кассе — debounce 300мс без мигания «Клиент не найден»; сохранение чека больше не запускает шторм из 9 рефетчей (тяжёлые ключи — `refetchType:'inactive'`).
- Префетч логина: удалён мёртвый 500-строчный запрос товаров, payload выровнен с экранным (`fields`-проекция).
- ETag-кеш axios ограничен LRU-100 и не кеширует поисковые запросы.
- Скраб графика выручки на Dashboard переведён с PanResponder на gesture-handler + reanimated worklet (UI-поток). История чеков в карточке клиента: state форм ушёл в модалки, мемо-строки, инкрементальный рендер.

## 5. Безопасность (backend, по явному запросу владельца)

- **`/api/uploads/*` (P1):** отдавал файлы всех тенантов без авторизации, включая документы сотрудников (паспорта), с `Cache-Control: public`; nginx-алиас отдавал с диска в обход NestJS. Двухуровневое лечение: документы сотрудников → приватное поддерево `uploads/private/<tenant>/`, выдача только через новый авторизованный tenant-проверенный `GET /api/employees/:id/documents/:docId/file` (`private, no-store`); nginx `deny all` на приватное поддерево; идемпотентный bootstrap при старте переносит уже загруженные документы (лог «Private documents bootstrap done»). Фото товаров/клиентов остаются capability-URL (UUIDv4) — `<img>`/expo-image не умеют JWT; легаси flat-basename fallback удалён.
- **`checks.fullUpdate` (P1):** не было cross-tenant guard'ов, которые есть в `create()` — чужие UUID протаскивали имена/телефоны/номера другого тенанта через JOIN. Добавлены те же guards + tenant-scoped JOIN в `getById`/`getAll` (защита в глубину, покрывает исторические записи).
- Marketing-эндпоинты получили class-validator DTO (раньше `@Body() dto: any`); CSV-импорт не отдаёт сырые ошибки драйвера; push-токен нельзя перехватить перерегистрацией из чужого тенанта.
- Бонус-находка: sentinel `_existing_` при редактировании интеграции записывался в БД буквально, затирая API-ключ — теперь сохраняет текущий ключ. ⚠️ Уже испорченные ключи не восстановимы — владельцам затронутых интеграций нужно один раз ввести ключ заново.

## 6. Native / Swift

Вердикт аудита по «переделать на Swift»: текущая Swift-инвестиция (liquid-glass бар) здоровая; сетку расписания возвращать в native **не нужно** (RN-сетка с worklet-синхронизацией уже выигрывает, мёртвая нативная сетка с реальными багами удалена из бинаря). Сделано:

- **Нативный date/time picker** (самый заметный не-нативный элемент, 8 экранов): iOS — UIDatePicker (inline-календарь для дат, барабаны для времени), ru-RU, тёмная тема, blur-backdrop вместо чёрного скрима; Android сохранил JS-пикер, перекрашенный в тему (нативный диалог Android игнорирует in-app переключатель темы). Props-контракт не изменился — 8 экранов не тронуты.
- Таб-бар: тройная белая кромка сведена к одной, адаптивной к тёмной теме; glow-ореол Кассы восстановлен (был срезан overflow:hidden); системно отменённый pan-жест больше не переключает таб; градиент стекла поверх материала (как обещал спек); мёртвые props (`bottomInset`, `intensity`) удалены end-to-end; `setWidgetData` за флагом `WIDGET_ENABLED=false` до возврата виджета.

## 7. Fallback-стратегии

- Иконки: правки только в карте маппинга — Android (тот же Lucide/SVG-рендер) выигрывает одинаково.
- Date picker: Android — прежний JS-пикер в цветах темы; контракт компонента не менялся.
- Native-модуль: Android по-прежнему получает JS-fallback (expo-blur / View) — контракт сохранён.
- Документы сотрудников: UI-потребителей URL не существовало (проверено grep) — смена семантики `fileUrl` безопасна; будущий UI обязан слать JWT (зафиксировано в `shared/types`).

## 8. Что НЕ сделано (честно)

- M9: фичи тарифов «Склад/Заказ-наряды/Экспорт» продаются, но не гейтятся — это продуктовое/биллинговое решение владельца, молча запирать табы нельзя. Мёртвый дубликат `GatedScreen.tsx` удалён.
- M15 (backend-фичи: закрытие зарплатного периода, копирование недели графика) — требуют отдельного решения владельца по контракту.
- Контекстные меню длинного нажатия (zeego/UIContextMenuInteraction) — рекомендация аудита, отложено как отдельная фича.
- Запуск на устройстве/симуляторе не выполнялся (правило владельца: тестирует сам на физическом iPhone; здесь — только компиляция/линт/тесты).

## 9. Acceptance-чеклист для владельца (физический iPhone)

1. **Расписание:** Ещё → Расписание 10 раз подряд — открывается каждый раз, без мигания; первый кадр — скелетон, затем сетка; скролл плавный; владельцев нет ни в сетке, ни в рейтинге; на «Сменах» работает ‹ месяц ›.
2. **Иконки:** Касса → выбор мастера/склада — аккуратные галочки без кружков; Склад — у позиций с низким остатком виден «!» в кружке (не точка); Зарплата — конверт читается; Подписка — галочки/крестики в списке фич.
3. **Касса:** скидка больше товаров → итог не уходит в минус, «Скидка» показывает применённую сумму; цена `1,5` через запятую не обнуляется; несуществующий номер → «Создать клиента» → клиент+авто сразу выбраны в чек.
4. **Офлайн:** Airplane mode → красная полоса «Нет соединения», любое сохранение быстро показывает «Ошибка», ничего не виснет.
5. **Push (после установки ИЗ ЭТОЙ сборки):** пуш приходит; тап открывает чек (в т.ч. из убитого приложения); после выхода из аккаунта пуши не приходят.
6. **Тёмная тема:** фильтр по дате в Журнале — тёмный нативный календарь на русском; верх таб-бара без жёсткой белой линии; вокруг Кассы мягкий glow.
7. **Журнал:** воронка → «Отложенные» с счётчиком; в карточке отложенного чека — зелёная «Принять оплату».
8. **Отчёты после 21:00 МСК:** «Сегодня» показывает текущий день, не вчерашний.
