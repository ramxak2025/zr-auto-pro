# Мульти-точки: несколько автосервисов у одного тенанта (2026-08-30)

## Проблема / motivation

Владельцы с несколькими автосервисами вели каждый в отдельном тенанте или в одном
без разделения. Заказ: суперадмин добавляет тенанту дополнительные точки
(название + адрес), тенант быстро переключается между точками, назначает мастеров
на точки, выбирает общую или раздельную базу клиентов, а чек показывает точку.

## Архитектура

**Модель (миграция `156_tenant_points.sql`)** — точка ортогональна tenant_id
(RLS-конвенция 112 не трогается, изоляция остаётся тенантной):

- `tenant_points` (id, tenant_id, name, address, sort_order, is_active) — RLS по
  паттерну 146. **НЕ путать с `tenant_locations`** («места» внутри двора,
  Round 14) — обе сущности живут параллельно.
- `user_points` — назначения сотрудников; ПУСТО для сотрудника = не ограничен
  (безопасный дефолт внедрения).
- `users.current_point_id` — серверно хранимый выбор точки (переключатель).
- `checks.point_id` — штампуется при создании из current_point_id автора.
- `clients.point_id` + `tenants.points_shared_clients` — при `false` список
  клиентов фильтруется точкой автора (`point_id = моя ИЛИ NULL`), новые клиенты
  рождаются на точке; NULL-клиенты (исторические, розничный) видны всем.

**Лимит точек = сколько создал суперадмин** (CRUD только в ЛК). 0–1 живая точка
= одноточечный режим: все новые UI скрыты, поведение прежнее.

**API** (backend `points/`, shared `createPointsApi` / `tenantsApi.points`):

- Тенант: `GET /points` (точки + memberIds + моя текущая), `POST /points/switch`
  (мастер — только на назначенные; user_management — свободно, null = «все»),
  `PUT /points/:id/members` (user_management).
- Суперадмин: `GET/POST /tenants/:id/points`, `PATCH/DELETE
/tenants/:id/points/:pointId` (DELETE = архив; чистит current_point_id).
- `PATCH /my-company` принимает `pointsSharedClients` (company_manage).
- `Check.point {id,name}` — в журнале/детали/доске; PDF (mobile orderPdf, web
  generateReceiptPdf/generateOrderPdf) печатают строку «Точка: …».

## Fallback-стратегия

- Старые клиенты приложения игнорируют новые поля (все аддитивные).
- Тенант без точек / одна точка — ни переключателя, ни экранов, ни бейджей.
- Мастер без назначений не ограничен; архив точки сбрасывает current_point_id.

## Acceptance criteria (проверка владельцем)

1. ЛК суперадмина → тенант → «Точки» → создать 2 точки с адресами.
2. Владельцем тенанта: на главной появился переключатель точек; в «Ещё → Точки»
   назначить мастера на точку Б; мастер видит только точку Б в переключателе.
3. Создать заказ, выбрав точку А — в детали/журнале и PDF видна «Точка: А».
4. Настройки компании → выключить «Общая база клиентов» → клиент, созданный на
   точке А, не виден в списке на точке Б (старые клиенты видны везде).
