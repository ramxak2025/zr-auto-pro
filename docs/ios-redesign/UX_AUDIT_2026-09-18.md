## 1. Дизайн-директива Autexa (источник правды для кода)

**Autexa на iPhone — это инструмент цеха, а не админка: спокойный чёрно-белый реестр, в котором на один экран приходится ровно один цветной сигнал и ровно одно главное число.** Типографика — одна шкала San Francisco из семи ступеней (34 / 28 / 22 / 17 / 15 / 13 / 11), жёсткий пол 11 pt, четыре веса (400/600/700/800, где 800 легален только у `display`), и отдельный числовой тир (`display` / `metric` / `money`) с `fontVariant: ['tabular-nums']` и `SF Pro Rounded` — деньги и остатки это единственное место, где у приложения есть собственный узнаваемый голос, и он типографический, а не цветовой. Палитра — нейтральная доминанта (`bg.canvas` / `bg.card` / `bg.muted` + три уровня текста) плюс ровно три семантических сигнала (`success` / `danger` / `warning`) и бренд-синий строго за интерактив; градиент разрешён ровно один раз на всё приложение — hero Главной, и он чернильный с SVG-материалом, а не сине-фиолетовый меш. Материал — плоские inset-grouped списки с hairline-разделителями, а нативное стекло (`AutexaLiquidGlassView`) только там, где слой физически плавает над контентом (таб-бар, футер кассы, бар выделения); движение — один мотив «поверхность поднимается и садится» из трёх длительностей (120 / 200 / 280 мс), вход пружиной, выход затуханием, **ноль entrance-анимаций внутри рециклируемых списков и ни одной бесконечной микроанимации рядом с данными**.

## 3. ВОЛНА 1 — восемь правок, максимум эффекта, минимум экранов

> Семь из восьми живут в `mobile/src/platform` и `mobile/src/components`. Восьмая — один новый общий компонент строки, который забирает работу у трёх экранов сразу.

### W1-1. `CachedImage`: `recyclingKey` + вариант `thumb`

**Файл:** `mobile/src/components/CachedImage.tsx` (+ call-sites: `ProductsScreen.tsx:296`, `ProductPickerScreen.tsx:160`, `ProductPickerModal.tsx:174`, `EquipmentScreen.tsx:568/1571/1736`, `UsersScreen.tsx:132`, `EmployeesScreen.tsx:139`, `DismissedEmployeesScreen.tsx:135`)

**Что меняем.** Добавить в `LegacyImageProps` проброс `recyclingKey?: string | null` прямо в `<Image>` — expo-image 3 его поддерживает (`node_modules/expo-image/build/Image.types.d.ts:194`, в проекте 0 вхождений). Ввести проп `variant?: 'thumb' | 'hero'` (дефолт `hero`, обратная совместимость):

- `thumb` → `transition={0}`, `placeholder={null}`, `backgroundColor: palette.bg.muted` прямо на стиле картинки;
- `hero` → текущие 200 мс + blurhash.

`DEFAULT_BLURHASH` сгенерирован под `#e5e7eb` и на тёмной карточке `#181b22` вспыхивает светлым на каждой рециклированной ячейке — в `thumb` он не нужен по определению, потому что подложка совпадает с карточкой.

**Эффект.** Уходит главный механизм жалобы: фото предыдущего товара больше не «перетекает» в следующую строку, и по списку не бежит полоса светлых вспышек. Побочно — меньше нативной работы на каждый recycle.

**Риск.** Низкий. `recyclingKey` меняет только момент сброса содержимого вью. Единственное, за чем следить: `variant="thumb"` нельзя ставить крупным одиночным фото (лайтбокс, `ProductDetailScreen.tsx:834`) — там фейд уместен.

### W1-2. `AnimatedCard`: одна форма дерева навсегда + вон из рециклируемых списков

**Файл:** `mobile/src/components/AnimatedCard.tsx` (+ `ProductsScreen.tsx:268`, `SuppliersScreen.tsx:111`)

**Что меняем.** Сейчас `skipAnimation` (строка 66) определяет **тип корневого элемента**: при skip — `<TouchableOpacity>` (строка ~92), иначе `<Animated.View><TouchableOpacity>` (строка ~113). В FlashList один и тот же mount получает то `index=3`, то `index=40` → пересечение `STAGGER_LIMIT=8` заставляет React размонтировать всё поддерево строки вместе с `CachedImage`.

1. Всегда рендерить `<Animated.View style={animatedStyle}>` снаружи, при skip просто `opacity: 1` — форма дерева становится инвариантом, и компонент физически не может вызвать ремонт поддерева ни у одного вызывающего.
2. В `ProductsScreen.tsx:268` и `SuppliersScreen.tsx:111` `AnimatedCard` из строки списка убрать совсем (строка переезжает на `PressableScale role="row"` из W1-6).
3. Перевести entrance с RN `Animated` на Reanimated 4 `entering={FadeIn.duration(200)}` — он по умолчанию уважает `ReduceMotion.System`, и ручная подписка на строках 43–51 (значение читается один раз при загрузке модуля!) уходит.

**Эффект.** Уходит второй, независимый источник мерцания. Плюс верх списка перестаёт «проявляться» на каждом возврате к началу — список просто есть.

**Риск.** Средний по площади: `AnimatedCard` используют многие экраны. Но правка делает поведение строго более предсказуемым; визуально меняется только то, что первые 8 карточек больше не фейдятся внутри списков. Проверить экраны, где `AnimatedCard` используется без `onPress` (там уже `Animated.View` — ветка не меняется).

### W1-3. Снять `removeClippedSubviews` со всех FlashList

**Файлы:** `ProductsScreen.tsx:2428`, `ProductPickerScreen.tsx:739`, `SuppliersScreen.tsx:689`, `CarsScreen.tsx:224`, `ServicesScreen.tsx:370`, `PurchaseOrdersScreen.tsx:415`, `InstallmentsScreen.tsx:207`, `CheckTrashScreen.tsx:308`, `BookingsScreen.tsx:319`, `ReviewsReputationScreen.tsx:989`, `EmployeeDetailScreen.tsx:564` (там он вообще на `ScrollView`, резать нечего)

**Что меняем.** Удалить проп. FlashList v2 его не читает — он уходит в `rest` и спредится на нижний ScrollView, где ячейки позиционированы абсолютно, и штатное отсечение по клип-ректу конфликтует с собственным рециклингом. На Складе заодно снять устаревший комментарий про «heavy CachedImage» (удержанием изображений теперь занимается `recyclingKey`) и добавить `drawDistance={800}` + `getItemType={() => 'product'}`.

**Обоснование — внутреннее, не теоретическое:** `ClientsScreen.tsx:876` и `ChecksScreen.tsx:2112` уже стоят с `removeClippedSubviews={false}` и развёрнутым комментарием владельца («дёргаются и пропадают», «то показывает, то нет, то мерцает»). Склад и подбор товара просто не получили этот фикс.

**Эффект.** Третий механизм мерцания снят. `drawDistance` 800 pt (~13 строк в обе стороны) убирает «догоняющие пустые блоки» при быстром флике.

**Риск.** Низкий, память — плюс несколько лёгких мемоизированных строк. На FlatList/ScrollView-экранах (`ScheduleScreen`, `DashboardScreen:4566`, `ReportsScreen:891`, `WarehouseAnalyticsScreen:403`) флаг тоже стоит снять — там он не виртуализация, а отцепление поддеревьев.

### W1-4. Палитра: три правки токенов, которые чинят 84 экрана

И привести `badgeColors` к одному правилу «фон `[50]` → текст `[700]`»: `orange[600]`→`orange[700]`, `indigo[600]`→`indigo[700]` (`theme/index.ts:204-205`), сделав `useBadgeColors()` единственным способом получить цвет бейджа (сейчас он применён в 1 файле, из-за чего `badgeColorsDark` в большинстве мест просто не задействуется).

**Риск.** Средний визуально — «серый» станет заметно темнее везде сразу, это изменит ощущение светлой темы. Комментарий в палитре защищает соответствие вебу — это осознанное расхождение, и его надо показать владельцу на скриншоте до/после. Технически риска нет.

## 8. Порядок работ и как принимать

1. **Волна 1 + P0-баги** — одна ветка, один PR. Проверки: `cd mobile && npm run typecheck && npm run lint && npx jest`.
2. **Приёмка владельцем на физическом iPhone** (это единственный способ подтвердить, что мерцание ушло — на симуляторе рециклинг ведёт себя иначе):
   - Склад, быстрый флик вверх-вниз 10 раз подряд по списку с фото: под названием товара **ни разу** не должно оказаться чужого фото, не должно быть светлых вспышек на тёмной теме и пустых блоков при разгоне;
   - вход на Склад из другого таба: список появляется целиком, без «сборки» первых восьми строк;
   - скролл-индикатор идёт ровно, строки одной высоты;
   - режим выделения: тап по «Отмена» закрывает выделение, а не открывает выбор склада;
   - тёмная тема: цена товара, себестоимость и «шт»/«л» читаются при ярком свете.
3. **Документ** — `docs/ios-redesign/WAREHOUSE_RECYCLING_FIX.md` (проблема, четыре механизма, фикс, fallback на FlatList, критерии приёмки) + `docs/ios-redesign/DESIGN_DIRECTIVE.md` (раздел 1 этого плана как источник правды) и ссылки на них из `FINAL_REPORT.md`.
4. Волны 2 и 3 — отдельными PR по темам, каждый со своим чек-листом приёмки. Ничего из Волны 3 не начинать, пока Волна 1 не подтверждена на устройстве: бóльшая часть хвоста — это дисциплина, а дисциплина поверх неисправленной причины не читается как улучшение.
