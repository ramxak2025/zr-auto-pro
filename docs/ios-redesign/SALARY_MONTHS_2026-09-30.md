# Зарплата и расходы по месяцу «за который» — mobile (2026-09-30)

Клиентская часть правки №3 (`docs/specs/2026-09-30-SALARY_MONTHS.md`, раздел 4) для
iOS/Android-приложения. Контракт закрыт в `shared/types/index.ts` и
`shared/api/createServices.ts` (коммит `b7bf86a9`): `SalaryMonthDetail.carryOver`,
`MasterSalary.carryOverAmount`, `salaryApi.createPayout({ …, periodMonth })`,
`expensesApi.getAll({ …, attribution })`, `periodMonth` в создании и правке расхода.
Backend (A3) делается параллельно, веб (B3: `SalaryPage`, `ExpensesPage`,
`EmployeeDetailPage`) уже готов — тексты и логика мобильной части выровнены с вебом.

## Проблема / motivation

Владелец выдаёт в октябре зарплату за сентябрь. Выплата попадала в отчёты октября (по
дате факта): «По зарплатам» за сентябрь показывал остаток 30 000, а октябрь — «выплачено
30 000» при нулевом начислении. Долг прошлого месяца в приложении негде было увидеть, а
чтобы его погасить, нужно было вручную листать карточку сотрудника на нужный месяц.

Правило, которое теперь держат все клиенты:

| Что                                                                                          | Считается по                        |
| -------------------------------------------------------------------------------------------- | ----------------------------------- |
| Отчёты «По зарплатам», «Сводный», «По расходам», «Расходы по категориям» в финансовом отчёте | месяцу «за который» (`periodMonth`) |
| Лента «Расходы», касса (`cashflow`), «Движение денег»                                        | дате факта (`date`)                 |

Выплата в октябре за сентябрь — это октябрьская строка в ленте и кассе (деньги ушли в
октябре) с бейджем «за сентябрь», но сентябрьская цифра в отчётах.

## Что видит пользователь

- **Форма выплаты** (карточка сотрудника и быстрое «Выдать» в списке): строка «За какой
  месяц — Сентябрь 2026». По умолчанию — открытый месяц. Тап раскрывает сетку из 13
  месяцев (текущий и 12 назад). Заголовок листа — «Выплата за сентябрь — Иван». Если месяц
  не текущий, под полем подпись «Выдаётся сегодня, учитывается за Сентябрь 2026».
  Сумма подставляется «К выплате» выбранного месяца, пока её не правили руками.
- **Карточка сотрудника** — блок «Не выплачено за прошлые месяцы»: «Сентябрь — 12 000 ₽ ·
  Выплатить». «Выплатить» открывает ту же форму с месяцем долга и суммой = остатком.
  Переплата показана серым «переплата 500 ₽» без кнопки: долг она не гасит. При двух и
  более долгах внизу строка «Итого».
- **Список «Зарплата»**: у сотрудника с долгом за прошлые месяцы под именем — «+ долг за
  прошлые: N ₽».
- **«Расходы»**: бейдж «за сентябрь» у расхода, если месяц «за который» не совпадает с
  месяцем даты. В форме — необязательное поле «За какой месяц» (пункт «По дате оплаты» —
  без назначения) с подсказкой «Отчёты и прибыль отнесут расход к этому месяцу; лента —
  по дате оплаты». У расхода-зеркала выплаты поле только для чтения (замок): месяц такого
  расхода задаёт сама выплата.
- **«Отчёты → Финансовый отчёт → Расходы по категориям»**: считаются по месяцу «за
  который»; сноска «По месяцу, за который расход. Лента «Расходы» и касса — по дате
  оплаты.»

## Архитектура

### Хелперы — `mobile/src/components/salary/salaryFormat.ts`

Чистые функции без React (тесты — `components/salary/__tests__/salaryMonths.test.ts`),
существующие экспорты не менялись.

| Функция                               | Что делает                                                                                               |
| ------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| `isMonthKey`                          | строгая проверка `YYYY-MM` (в отличие от `parseMonthKey` не подменяет мусор текущим месяцем)             |
| `monthKeyLabel` / `monthKeyInline`    | «Сентябрь 2026» для значений полей / «сентябрь» для бегущего текста; мусор → пустая строка               |
| `payoutSheetTitle`                    | «Выплата за сентябрь — Иван»; год добавляется только для месяца не из текущего года                      |
| `recentMonthOptions`                  | текущий месяц + 12 назад, свежие сверху; `include` оставляет в списке выбранный месяц старше окна        |
| `monthKeyOfDate` / `periodBadgeLabel` | месяц даты факта (для чистой даты — из строки, без сдвига по поясу) и текст бейджа «за сентябрь»         |
| `carryOverRows`                       | строки блока долгов из `carryOver.months` (порядок контракта, округление до рубля, нули отбрасываются)   |
| `buildPayoutSuggestions`              | «К выплате» по месяцам: остаток открытого месяца + долги из `carryOver`; переплата и нули — не подсказка |

### `MonthPickerField.tsx` — выбор месяца

Один компонент на выплату и на расход. Раскрывается **инлайн** (сетка двух колонок), а не
вторым `Modal`: обе формы сами живут в `Modal`, а вложенные RN-модалы на iOS ведут себя
непредсказуемо (та же причина, что в `CheckCreateScreen` и `ProductPickerModal`).
Особенности:

- `nullLabel` («По дате оплаты») добавляет пункт «не назначен» — для расхода; для выплаты
  месяц обязателен.
- `disabled` — только чтение с иконкой замка (расход-зеркало выплаты).
- При раскрытии закрывает клавиатуру: цифровая клавиатура поля суммы закрыла бы нижние
  месяцы сетки.
- `haptic('select')` через `platform/haptics.ts`; анимаций нет вовсе, поэтому Reduce Motion
  соблюдается сам собой; чипы — `accessibilityRole="radio"` + `accessibilityState.checked`.

### `PayoutForm` (`SalaryEmployeeCard.tsx`)

- Месяц контролируемый: `monthKey` хранит родитель (ему нужен заголовок листа),
  `onMonthChange` меняет его. Сумма — производное состояние: `typedAmount ?? подсказка
месяца`. Пока сумму не правили, она следует за выбранным месяцем и за поздно пришедшей
  подсказкой; «Подставить» возвращает её одним тапом.
- `onSubmit` отдаёт `periodMonth` **всегда** — выплата никогда не уходит без явного месяца
  (сервер иначе подставил бы месяц факта). Обе мутации (карточка и быстрое «Выдать»)
  передают его в `salaryApi.createPayout`.
- Подсказки берутся из `buildPayoutSuggestions(data, monthKey)`. Пока React Query держит
  снимок прежней цели (`placeholderData: prev => prev`, `isPlaceholderData`), подсказки
  пустые — чужая сумма в форме не появится.
- «Выдать» из карточки сбрасывает месяц на открытый (`openPayout`); «Выплатить» у долга —
  на месяц долга (`openDebtPayout`).

### Блок «Не выплачено за прошлые месяцы» (`CarryOverSection`)

Стоит после сетки итогов карточки. Данные — только `carryOver.months` (`total` и месяцы
приходят с деталью месяца, отдельного запроса нет). Кнопка «Выплатить» видна только держателю
права на выплаты (`canManagePayouts`) — как «Выдать» в самой карточке.

### `SalaryScreen.tsx`

- `EmployeeRow`: строка «+ долг за прошлые: N ₽» из `master.carryOverAmount` (округление до
  рубля; ≤ 0 и отсутствие поля — строки нет).
- `OwnerSalaryList`: `quickMonthKey` (по умолчанию открытый месяц списка, сбрасывается при
  каждом открытии листа). Подсказки суммы: если деталь месяца сотрудника уже в кэше и
  относится к тому же сотруднику и месяцу — `buildPayoutSuggestions`, иначе остаток из
  строки списка (известен сразу). Плашки «не зафиксировано / не просмотрено» относятся к
  месяцу списка и скрываются при выборе другого месяца.
- Форма «Выплата вне программы» не менялась: у неё уже есть собственный выбор месяца.

### `ExpensesScreen.tsx`

- Бейдж — `periodBadgeLabel(item.periodMonth, item.date)`; год добавляется, только если он
  отличается от года даты.
- `periodMonth` в форме — `string | null` (`null` — «По дате оплаты»). Создание шлёт поле,
  только если месяц выбран; правка — только если он **изменён** (`null` снимает
  назначение). Так старый расход, у которого месяца не было, не получает его молча.
- Расход-зеркало выплаты определяется клиентом по точному имени категории «Зарплата»
  (по нему же ищет сервер): месяц такого расхода задаёт выплата, а отличающийся
  `periodMonth` сервер отклонил бы 400. Поэтому поле заблокировано и в запрос не попадает.
  Блокировка следит и за категорией, выбранной в форме сейчас.

### `ReportsScreen.tsx`

`expenses` запрашиваются с `attribution: 'period'`. В ключ добавлен суффикс `'period'`
(`['expenses', 'by-period', from, to, 'period']`): слот с прежней привязкой по дате оплаты,
сохранённый на диске старой версией, не должен показаться данными нового вида. Заголовки
разделов HTML/Numbers-экспорта переименованы вместе со сноской: «Расходы по категориям
(по месяцу, за который расход)».

### Кэш

- `['expenses', …]` с `attribution` — **отдельный вариант ключа**, лента и агрегаты его не
  делят. Ключ отчёта заменил прежний слот 1:1, число вариантов не выросло.
  `VARIANT_CAPS.expenses = 3` проверен, `persistentCache.helpers.ts` не менялся.
- `'salary-employee-month'` в whitelist не входит — карточка месяца не персистится, что и
  нужно (долг — свежие серверные цифры). `placeholderData: prev => prev` не отключался.
- После выплаты и после создания/правки расхода дополнительно инвалидируется `['report-run']`
  (универсальные отчёты «По зарплатам» / «Сводный» / «По расходам», `staleTime` 30 с) —
  иначе отчёт мог показать цифры «до выплаты».

## Fallback: старый backend (до A3)

| Чего нет на сервере                  | Поведение приложения                                                                                                                   |
| ------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------- |
| `carryOver` в детали месяца          | `carryOverRows(undefined)` → блока долгов нет; подсказка суммы — только остаток открытого месяца                                       |
| `carryOverAmount` в строке списка    | `?? 0` → строки «+ долг за прошлые» нет                                                                                                |
| `attribution` у `GET /expenses`      | параметр молча игнорируется (400 нет), «Расходы по категориям» считаются по дате факта; сноска расходится с данными до выкатки backend |
| Ограничения на `periodMonth` расхода | поле не блокируется сервером, но клиент всё равно не шлёт месяц для расхода-зеркала                                                    |

`createPayout` с явным `periodMonth` старый backend принимал и раньше (быстрое «Выдать»
уже передавало месяц списка), поэтому форма с выбором месяца на нём работает.
Native-модулей эта правка не касается: поведение одинаково на всех версиях iOS.

## Android

Весь код — общий (`.tsx` без платформенных суффиксов), iOS-only API нет: `View`,
`TouchableOpacity`, `Keyboard`, иконки через шим `@expo/vector-icons`, замапленные
имена (`time-outline`, `calendar-outline`, `chevron-up/down`, `lock-closed-outline`,
`checkmark`). Вложенных модалов нет. Формы с `TextInput` остаются внутри существующего
`Modal` (KeyboardAware). Android-эмулятор в этой работе не запускался.

## Допущения

1. Регистр месяцев — как в вебе: строчные в бегущем тексте и заголовке листа («Выплата за
   сентябрь», «за сентябрь»), заглавные в значениях полей и блоке долгов («Сентябрь 2026»).
2. «Текущий месяц» (окно пикера, подпись «Выдаётся сегодня…», год в бейдже) считается по
   времени устройства; веб — по календарю автосервиса. Расхождение возможно только у
   границы месяцев и при разных часовых поясах устройства и автосервиса.
3. Блок долгов показывается, только когда есть долг или переплата (не пустой «Нет долгов»).
4. Заголовок листа выплаты не содержит года для текущего года: `Modal` не усекает длинные
   заголовки, а полный «Сентябрь 2026» стоит в строке поля.
5. Расход-зеркало выплаты определяется по имени категории «Зарплата» (связь `expense_id`
   клиенту не отдаётся). У «Выплаты вне программы» месяц редактируется — сервер это допускает.
6. Мобильная подпись в списке — «+ долг за прошлые: N ₽» (по спеке); веб показывает бейдж
   «Долг за прошлые: N ₽». Тоста «учтена за <месяц>» в мобильном приложении нет: месяц виден
   в заголовке листа и подписи, после выдачи — хаптик успеха.
7. Чип «Выдать» в строке списка по-прежнему виден только при остатке открытого месяца > 0,5 ₽.
   Если открытый месяц выплачен, а долг за прошлый остался, платить через блок в карточке
   («Выплатить») либо выбрать месяц в форме быстрой выдачи.
8. Заголовки экспорта («Расходы по категориям …») в `ReportsScreen` переименованы вместе со
   сноской, чтобы файл не расходился с экраном.

  — чек-лист для ручной проверки.

  `attribution` проверено по контракту `shared/` и по коду веб-реализации B3, а не на живом
