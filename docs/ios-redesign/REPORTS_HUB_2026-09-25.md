# Раздел «Отчёты» — хаб и универсальный экран отчёта (mobile, 2026-09-25)

Клиентская часть правки №3 (`docs/specs/2026-09-25-REPORTS.md`, раздел 2) для
iOS/Android-приложения. Контракт закрыт в `shared/types/index.ts` (секция
«КОНСТРУКТОР ОТЧЁТОВ»), каталог — `shared/reports/catalog.ts`, API-фабрика —
`createReportBuilderApi` (`reportBuilderApi` в `mobile/src/api/services.ts`).
Backend (`backend/src/reports/builder/`) делается параллельно; экраны спроектированы
строго по контракту и проверялись на dev-моке `ReportResult` (мок в код не вошёл).

Сюда же — правка №4 (`docs/specs/2026-09-25-CALL_FUNNEL.md`): состояния виджета
«Воронка звонков» на главной.

## Проблема / motivation

Владелец просил один раздел, где выбираешь **какой** отчёт, **за какой** период и
**по кому** (мастера, поставщики, сотрудники…) и получаешь таблицу с итогом и PDF.
В приложении был только «Финансовый отчёт» (`ReportsScreen`) — большой экран под
одну задачу (прибыль/P&L), без сущностных фильтров и без общего механизма «новый
отчёт = новый SQL». Одиннадцать согласованных отчётов не могли жить одиннадцатью
экранами.

## Архитектура

### Маршруты (`mobile/src/navigation/AppNavigator.tsx`, `MoreStack`)

| Маршрут                    | Экран                                    | Гейт                             |
| -------------------------- | ---------------------------------------- | -------------------------------- |
| `Reports`                  | `screens/reports/ReportsHubScreen` — хаб | фича `reports_view` (как раньше) |
| `FinancialReport`          | прежний `ReportsScreen` без изменений    | фича `reports_view`              |
| `ReportRun` `{ reportId }` | `screens/reports/ReportRunScreen`        | фича `reports_view`              |

Пункт «Отчёты» в «Ещё» (`MoreScreen.tsx`) ведёт в хаб; подпись обновлена
(«Сводный, по мастерам, зарплатам, поставщикам, товарам»). Клиентский гейт пункта
остался `financial_reports` — `MenuItem` поддерживает одно право; для ролей без
финансов, но с правом на отдельный отчёт (завскладом → «По товарам») сервер отчёт
отдаст, но пункт в «Ещё» они не увидят. Открытый вопрос (нужен `permissionAny`
в `MoreScreen`, вне зоны этой правки).

### Хаб (`ReportsHubScreen.tsx`)

- Карточки из `REPORT_CATALOG`, группы по `group` в порядке `summary → money →
people → stock` (`REPORT_GROUP_LABELS`), иконки/акценты — `REPORT_VISUALS`
  (имена Ionicons, которые есть в lucide-шиме).
- Доступность — только с сервера: `GET /reports/builder/catalog` → `available/reason`.
  Недоступные скрыты; owner-class (director/superadmin) видит их серым с `reason`
  («У компании один филиал»).
- Первая карточка «Финансовый отчёт — подробно» → `FinancialReport`
  (при `financial_reports`). Из старого экрана ничего не потеряно.
- Кэш: `['report-catalog']` в whitelist `persistentCache` + `placeholderData` —
  хаб рисуется мгновенно на холодном старте. На `pressIn` карточки греется
  `['report-filter-options', kind]`, чтобы шторка фильтра открывалась без спиннера.
- Состояния: skeleton (нет кэша), `QueryErrorState` с текстом сервера, empty-state
  «Нет доступных отчётов» (если нет ни одного отчёта и нет финансов).

### Экран отчёта (`ReportRunScreen.tsx`) — как рендерится `ReportResult`

Экран — **один вертикальный `FlashList`**. Управление лежит в `ListHeaderComponent`,
а результат разложен в плоский массив элементов:

```
kpis → table-header → row × N → totals → truncated?
     → (section-title → section-header → section-row × M → section-totals | section-empty) × K
     → method → footer
```

- **KPI** (`ReportKpiGrid`) — плитки по две в ряд; значение по `type`, `tone`
  красит число, `deltaPercent` — пилюля со стрелкой; `hint` открывается тапом (Alert).
- **Таблица** (`ReportTable.tsx`) — строки являются элементами FlashList, поэтому
  500 строк виртуализируются. Заголовок закреплён через `stickyHeaderIndices`
  FlashList v2. Итог — оверлей снизу над таб-баром, пока таблица не долистана
  (по `onViewableItemsChanged`: последний видимый элемент — ещё строка таблицы).
- **Sticky-колонка и горизонтальный скролл.** Нет ни одного вложенного
  `ScrollView`: у таблицы один `SharedValue scrollX` (`makeMutable`, свой на
  каждую секцию). Каждая строка = `[первая ячейка фиксированной ширины] +
[обрезанная область, внутри — Animated.View с translateX: -scrollX]`.
  Pan-жест (`react-native-gesture-handler`) на любой строке двигает общий
  `scrollX` на UI-потоке: `activeOffsetX ±8 / failOffsetY ±10` — горизонталь
  забирает таблица, вертикаль остаётся списку (принцип swipeable-строк);
  отпускание — `withDecay` с `clamp` и rubber-band, край — `withSpring`.
  Тень на границе sticky-колонки появляется при `scrollX > 0`. Высоты строк
  фиксированы (46/44/48) — FlashList не перемеряет ячейки.
- **Ширины колонок** — по `type` (money 112, int 78, percent 84, text 136…) ×
  `column.width`; sticky-колонка 40 % ширины (124–184 pt). Узкая таблица
  растягивается на всю карточку.
- **Форматирование** — единый `utils/reportFormat.ts` (деньги с копейками только
  когда они есть, проценты с одним знаком, `date`/`datetime` в поясе автосервиса,
  `signed` → красный/зелёный, `_tone` → тонированная строка, `null` → «—»).
  Числовые колонки выровнены справа (`cellAlign`).
- **Сортировка** — тап по заголовку: числа сначала по убыванию, текст по алфавиту,
  второй тап переворачивает, третий возвращает порядок сервера. Итог не сортируется.
- **Переходы по строкам** — `_href` (маршрут web) маппится в экраны mobile
  (`/clients/:id → ClientDetail`, `/suppliers → SupplierDetail`, `/products →
ProductDetail`, `/employees|/users → EmployeeDetail`, `/cars → CarDetail`);
  строка без известного маршрута не кликабельна.
- **Управление**: 7 пресетов периода как в `ReportsScreen`; «Месяц» — пейджер
  месяцев (прошлые — целиком, текущий — по сегодня, чтобы `deltaPercent` не
  сравнивал неполный месяц с полным); произвольный диапазон через
  `DateTimePickerModal`; сущностный фильтр — `ReportFilterSheet` (BottomSheet,
  поиск, мультивыбор, «Все» по умолчанию, чипы выбранных с «×»); `groupBy` —
  сегменты. Авто-запуск при смене пресета / месяца / фильтра / группировки;
  для произвольных дат — кнопка «Сформировать» (она же принудительный refetch).
  Клиентская валидация периода дублирует серверную (начало ≤ конец, ≤ 366 дней).
- **Состояния**: предыдущий результат остаётся на экране, пока грузится новый
  (`placeholderData`, в подзаголовке «Обновляется…»); первый запуск — skeleton;
  400/403 — `QueryErrorState` с текстом сервера (для 403 — заголовок «Нет доступа
  к отчёту»); пустые строки — empty-state «Нет данных за период» (KPI при этом
  остаются); `meta.truncated` — подсказка про лимит строк.
- **Подпись** — «Сформирован ДД.ММ.ГГ ЧЧ:ММ · филиал …» из `generatedAt` +
  `meta.pointName` (или «все филиалы» при `scope: 'all'`). **Методика** —
  `method` из каталога + `notes` сервера.

### Экспорт PDF (`utils/reportPdf.ts`)

`buildReportPdfHtml(result, opts)` — чистая функция по образцу `orderPdf.ts`:
шапка (компания / отчёт / период / фильтры / филиал / дата), KPI (таблица 4×N,
без flex-wrap — print-движки его теряют), основная таблица с `tfoot`-итогом,
секции, «Методика», футер. Ориентация: альбомный A4, если в какой-то таблице
≥ 7 колонок (`isWideReport`), иначе книжный — размеры страницы передаются в
`expo-print` через `width/height` (595×842 / 842×595 pt) плюс `@page`.
`shareReportPdf` поднимает `expo-print`/`expo-sharing` лениво (guarded require —
как `orderPdf`). Всё из данных экранируется `escapeHtml`.

### Кэш (`utils/persistentCache.helpers.ts`)

В whitelist добавлены `report-catalog`, `report-filter-options`, `report-run`
(последний с `VARIANT_CAPS = 3`). Как и `financial-report`, снимок восстанавливается
с реальным `updatedAt` → на mount всегда refetch; старые цифры живут до первого
ответа сервера.

## Виджет «Воронка звонков» (`DashboardScreen.tsx` → `CallFunnelWidget`)

По `CallFunnel.telephony`:

| Состояние                       | Что видит владелец                                                                                                                                                                                                     |
| ------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `telephony.connected === false` | Карточка «Подключите телефонию — и здесь появится воронка обращений…» + кнопка «Подключить телефонию» → `Main → MoreTab → Integrations` (кнопка только при `settings_manage`)                                          |
| `telephony.error`               | «Не удалось получить звонки: <текст>» + «Повторить» (refetch, во время запроса — «Обновляем…»)                                                                                                                         |
| данные                          | Две полосы по четыре плитки: Звонков · Дозвонились · Пропущено · Не перезвонили (оранжевый акцент, если > 0) и Приехало · Чеков · Выручка (компактно) · Конверсия; в шапке — месяц и провайдер («МоиЗвонки» / «Mango») |
| нет `telephony` (старый бэкенд) | Прежние четыре плитки                                                                                                                                                                                                  |

Виджет по-прежнему живёт только в стеке `AdminDashboard` — у мастера места не занимает.

## Fallback-стратегия

- Android: RNGH + Reanimated + `expo-linear-gradient` кросс-платформенные;
  `Platform` используется только для отступа под таб-бар (`contentInset` на iOS,
  `paddingBottom` на Android). Никаких iOS-only API в общих файлах.
- Нативные модули печати не слинкованы (старая сборка) → мягкий алерт «Экспорт
  недоступен», экран работает.
- Бэкенд без `/reports/builder/*` (ещё не выкачен) → хаб показывает карточку
  «Финансовый отчёт — подробно» и `QueryErrorState` с текстом сервера; старый
  финансовый отчёт доступен всегда.
- Бэкенд без `telephony` в воронке → виджет как раньше.

## Acceptance criteria (владелец, физический iPhone)

1. «Ещё → Отчёты» открывает хаб: группы «Финансы / Сводные / Деньги / Люди / Склад»;
   первая карточка «Финансовый отчёт — подробно» открывает прежний экран без
   изменений. Баг: пропал старый экран или его пункты.
2. Тап по «По мастерам» → экран с пресетами; отчёт за текущий месяц формируется
   сам, без нажатия кнопки. Смена пресета «Неделя» → цифры обновляются, старые не
   мигают пустотой. Баг: пустой кадр между периодами.
3. Таблица: горизонтальный свайп по любой строке двигает все строки вместе,
   первая колонка стоит на месте; вертикальный скролл не мешает. Заголовок
   закрепляется сверху, итог — снизу, пока таблица не долистана. Баг: дёргание,
   рассинхрон строк, свайп открывает «назад».
4. Тап по заголовку числовой колонки сортирует по убыванию, второй — по
   возрастанию, третий — исходный порядок; итог не двигается.
5. Фильтр «Мастера»: шторка с поиском, выбрать двоих → чипы под пресетами, отчёт
   пересчитан; «×» на чипе снимает мастера. «Все» — по умолчанию.
6. «Произвольный»: даты меняются пикером, отчёт НЕ пересчитывается до кнопки
   «Сформировать»; период > 366 дней — кнопка выключена, подсказка снизу.
7. Иконка «Поделиться» в шапке → share-sheet с PDF: шапка, KPI, таблица с итогом,
   секции, «Методика»; у «По мастерам» (13 колонок) — альбомный лист.
8. Главная → «Воронка звонков»: при отключённой телефонии — карточка с кнопкой
   «Подключить телефонию» (ведёт в Интеграции); при ошибке провайдера — текст и
   «Повторить»; при данных — восемь плиток, «Не перезвонили» оранжевая, если > 0.

## Проверки

- `cd mobile && npm run typecheck && npm run lint && npx jest` — зелёные (jest включает
  `reportPdf.test.ts` и `reportFormat.test.ts`). Native не менялся — prebuild не нужен.
- Контракт против живого backend: все 11 отчётов, снятые с локального сервера
  (`/reports/builder/:id`, demo-tenant), прогнаны через `buildReportPdfHtml` и
  `sortRows` временным jest-тестом — без исключений; типы колонок и KPI
  только из известного набора; `_tone: 'default'` от сервера обрабатывается;
  `points` приходит со `scope: 'all'` → подпись «все филиалы».
- iOS Simulator (iPhone 17 Pro, свежая Debug-сборка dev-client, Metro на 8082):
  экраны гонялись через временный dev-preview без логина (удалён) и управлялись
  через CDP (Hermes inspector) — тапы CGEvent до окна симулятора не дошли из-за
  перекрывающихся окон соседних симуляторов. Проверено визуально: хаб с живым
  каталогом; экран отчёта (пресеты, пейджер месяца, фильтр-чип, KPI с дельтами,
  таблица со sticky-колонкой, тень на границе при сдвиге, сортировка с
  индикатором, тонированная строка, шторка фильтра с поиском, смена периода,
  sticky-заголовок, оверлей «Итого» по координатам `getLayout`, «Методика»,
  подпись); виджет воронки в четырёх состояниях. НЕ проверено реальным касанием:
  Pan-жест горизонтальной прокрутки (сдвиг проверялся программно через
  SharedValue) и share-sheet PDF — приёмка владельцем по чек-листу выше.
- Найдено и исправлено в прогоне: `GestureDetector` без корня RNGH (у приложения
  нет глобального `GestureHandlerRootView`) → экран отчёта обёрнут в свой корень;
  viewability FlashList v2 включает overscan → оверлей итога переведён на
  `onScroll` + `getLayout`; подпись «Не перезвонили» в плитке воронки — две строки.
