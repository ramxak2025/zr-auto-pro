# Редизайн десктопной админки (правка №1, 2026-09-25)

**Запрос владельца.** «Преобразить десктопную версию сайта — с неё часто работают, а не
только из приложения». Речь про рабочую админку (`frontend/`, маршруты под `/dashboard`,
`/checks`, `/products`, …), НЕ про лендинг `autexa.pw` (`src/pages/landing/**` не трогаем).
Инструменты по требованию владельца: скилл `frontend-design` (дизайн и визуальная
система), `web-design-guidelines` (UX/UI-аудит), `vercel-react-best-practices`
(качество React-реализации).

## Кто пользователь и что важно

Владелец, директор, администратор автосервиса за компьютером весь день: касса, журнал,
склад, зарплата, отчёты. Экраны 1280–1920 px, мышь + клавиатура, десятки операций в час.
Ценится: плотность без каши, мгновенное сканирование таблиц и сумм, предсказуемая
навигация, отсутствие «маркетинговых» украшений. Тот же продукт, что iOS-приложение
(синий `#2563eb`, спокойные нейтральные, lucide-иконки, русский язык интерфейса), но в
десктопной идиоме: боковая навигация, рабочие таблицы, панели фильтров.

Мобильный веб (PWA на телефоне) продолжает работать: нижние табы `mobileTabItems`,
адаптивность — сохранить. Приоритет — десктоп, но ничего не ломать на 375 px.

## Фаза A — дизайн-лид (агент W1)

1. **Аудит** ключевых экранов скиллом `web-design-guidelines` (Главная, Журнал, Касса,
   Склад, Клиенты, Зарплата, Отчёты, Настройки) → `docs/web-redesign/AUDIT.md`: конкретные
   проблемы (иерархия, контраст, размеры кликабельных зон, фокус, консистентность отступов и
   типографики, состояния пусто/загрузка/ошибка, таблицы), с приоритетами.
2. **Визуальная система** (скилл `frontend-design`) → код + `docs/web-redesign/DESIGN_SYSTEM.md`:
   - токены как CSS-переменные в `index.css` + расширение `tailwind.config.js`: цвет
     (поверхности, границы, текст 3 уровня, акцент, семантика успех/внимание/ошибка),
     радиусы, тени (мягкие, 1–2 уровня), типографическая шкала (заголовок страницы, секции,
     таблица, подписи), плотность (высоты строк таблиц/инпутов 36–40 px), фокус-кольцо;
   - шрифт: самохостинг обязателен (Google Fonts режется у операторов РФ). Уже есть
     `Onest` (woff2 в `public/fonts`) — можно взять его для админки, либо системный стек.
     `Inter` сейчас нигде не грузится — это фолбэк по факту;
   - примитивы в `frontend/src/ui/` (новая папка, экспорт через `index.ts`): `Button`
     (варианты primary/secondary/ghost/danger, размеры, loading, иконка), `IconButton`,
     `Card`/`CardHeader`, `StatCard` (KPI), `DataTable` (липкий заголовок, числовые колонки
     справа, строка итого, сортировка, состояния loading/empty/error, плотный режим),
     `Toolbar`/`FilterBar`, `Input`/`Select`/`Textarea`/`Checkbox`/`RadioGroup`, `Tabs`,
     `SegmentedControl`, `Badge`/`StatusPill`, `Drawer` (боковая панель для деталей),
     `Skeleton`, `Tooltip`. Существующие `Modal`, `Switch`, `EmptyState`, `PageHeader`,
     `Pagination`, `SearchInput`, `DatePeriodPicker`, `QueryState`, `ConfirmDialog` —
     перестилизовать НА МЕСТЕ, сохранив API (их импортируют десятки страниц);
   - правила: 8-px сетка, один акцент на экран, семантические цвета только по смыслу,
     hover только `@media (hover)`, фокус видим, hit-area ≥ 32 px, анимации ≤ 200 мс и
     уважают `prefers-reduced-motion`.
3. **Оболочка приложения** — `Layout.tsx`: боковая панель с группами (Работа: Главная,
   Касса, Доска работ, Журнал · Клиенты: Клиенты, Автомобили, Записи/Планирование, Звонки,
   Маркетинг · Склад: Склад, Услуги, Поставщики, Заказы поставщикам, Оборудование · Деньги:
   Движение денег, Кассовая смена, Рассрочка, Расходы, Зарплата, Отчёты · Компания:
   Расписание, Сотрудники, Пользователи, Филиалы, База знаний, Настройки, Интеграции),
   сворачивание до иконок с запоминанием в `localStorage`, активный пункт, счётчики там, где
   они уже есть; верхняя панель: название компании/филиал (`PointIndicator`), быстрые
   действия («Новый чек»), пользователь/выход. Права/гейты (`permission`, `featureKey`) и
   `mobileTabItems` — как были. Маршруты не менять.
4. **Эталонная страница** — `DashboardPage.tsx` полностью в новой системе + новый виджет
   «Воронка звонков» по `docs/specs/2026-09-25-CALL_FUNNEL.md` (`reportsApi.callFunnel`,
   состояния «телефония не подключена» / ошибка / данные).
5. **Гайд для страниц фазы B** — раздел «Как мигрировать страницу» в `DESIGN_SYSTEM.md`:
   шаблон структуры страницы (`PageHeader` → `Toolbar` → контент), какие классы чем заменять,
   чек-лист приёмки, скриншоты до/после Главной (Playwright, скилл `webapp-testing`,
   локальный стек: `backend` на :3000 + `vite` на :5173, база `autexa-pg`).

Не трогать в фазе A: остальные страницы `src/pages/**` (их возьмут агенты фазы B),
`src/api/**`, react-query ключи, бизнес-логику, `lazyWithRetry`, лендинг.

## Фаза B — страницы (5 параллельных агентов, после W1)

Каждый переводит свою группу страниц на систему из `DESIGN_SYSTEM.md`, не меняя поведение,
запросы и маршруты; новые фичи — по спекам:

- **G1 Касса и журнал**: `ChecksPage`, `CheckCreatePage`, `CheckDetailPage`, `WorkBoardPage`,
  `CashShiftPage`, `RetailChecksPage` (+ VIN-режим поиска в Кассе по `2026-09-25-VIN.md`).
- **G2 Клиенты и авто**: `ClientsPage`, `ClientDetailPage`, `CarsPage`, `ImportClientsCarsPage`,
  `CallsPage`, `MarketingPage` + компоненты `marketing/`, `InstallmentsPage`, `PlanningPage`
  (+ поле VIN в формах авто, VIN в карточках, поиск по VIN).
- **G3 Склад и поставщики**: `ProductsPage`, `ServicesPage`, `SuppliersPage`,
  `SupplierDetailPage`, `PurchaseOrders*`, `EquipmentPage`.
- **G4 Деньги и отчёты**: `SalaryPage`, `ExpensesPage`, `CashFlowPage`, новый раздел
  «Отчёты» (`ReportsPage` → хаб, `/reports/:reportId`, экспорт Excel/PDF по
  `2026-09-25-REPORTS.md`), старый финансовый отчёт → `/reports/financial`.
- **G5 Компания**: `SchedulePage`, `EmployeesPage`, `EmployeeDetailPage`, `UsersPage`,
  `PointsPage`, `CompanySettingsPage` (+ блок VIN), `IntegrationsPage`,
  `NotificationSettingsPage`, `TariffPage`, `MorePage`, `KnowledgeBase*`, `pages/admin/*`.

## Приёмка

`cd frontend && npm run typecheck && npm run lint && npm run build`; скриншоты Playwright
на 1440 px каждой страницы до/после в `docs/web-redesign/screenshots/`; ни одного
изменения в запросах к API (diff `src/api/**` пустой, кроме новых методов по спекам);
мобильная ширина 375 px — страницы открываются и скроллятся.
