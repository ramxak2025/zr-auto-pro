# UX/UI-аудит десктопной админки Autexa (фаза A, 2026-09-25)

**Что смотрели.** Восемь ключевых экранов веб-админки на 1440×900 и 375 px (Главная, Журнал,
Касса, Склад, Клиенты, Зарплата, Отчёты, Настройки) плюс оболочку `Layout.tsx`. Метод: скриншоты
«до» (`screenshots/before-*.png`, Playwright, локальный стек), построчный разбор кода по
чек-листу Web Interface Guidelines (скилл `web-design-guidelines`) и продуктовым эвристикам
десктопа из `BRIEF.md` (плотность, сканируемость таблиц и сумм, предсказуемая навигация,
отсутствие декора). Прошлый аудит `docs/WEB_LK_UIUX_AUDIT.md` (64 находки, ~42 страницы) остаётся
в силе — здесь он не повторяется, а дополняется тем, что стало видно именно на десктопе.

Приоритеты: **P0** — вводит в заблуждение по деньгам/данным или делает функцию недоступной;
**P1** — заметно мешает ежедневной работе за компьютером; **P2** — полировка.

## 2. По экранам

### 2.1 Главная (`DashboardPage.tsx`, 1283 строки) — переделана в фазе A

- P0 — 4 виджета без `isError` (`schedule-today`, `deferred-reminders`, `users`/`schedule`, `dashboard-v2`): при сбое сети «Сотрудники сегодня», «Отложенные чеки», «Чистая прибыль» исчезают — читается как «никого нет / отложенных нет».
- P0 — график при ошибке показывает «Нет данных» (`isLoading=false`, `data=undefined`).
- P1 — тёмная градиентная карточка графика: единственная тёмная поверхность в светлом инструменте, подписи 9–11 px `slate-400`, `preserveAspectRatio="none"` растягивает толщину линии, нет оси Y и hover-значений; значения читались только в горизонтальной ленте чипов 9 px с видимым скроллбаром (`scrollbar-hide` не был определён).
- P1 — статусы сотрудников через эмодзи (🏥🌙❌✅⏳🥇) без текста для скринридера; подписи 9–10 px; статус целиком — только в `title`.
- P2 — «Быстрые действия» ниже фолда и дублируют меню; H1 — приветствие без стабильного имени страницы; переходы через `<button onClick={navigate}>` вместо `<Link>`; стрелки периода 28 px; три стека дат в одном файле; `rounded-2xl/3xl/xl` вперемешку.

**Что сделано в фазе A:** страница собрана заново на `PageHeader` + `StatCard` + `Card/CardHeader`; светлый график с осью Y, hover-подсказкой и `vector-effect`; все виджеты — с состояниями loading/error(+Повторить)/empty; сотрудники — цвет + подпись + значок, каждый — `<Link>`; новый виджет «Воронка звонков» (`calls_view`); KPI-полоса на уже существующем запросе `['dashboard-v2']`. См. `screenshots/after-dashboard-1440.png`.

### 2.2 Журнал (`ChecksPage.tsx`, 973 строки) — фаза B / G1

- P0 — сводка смешивает области: «Всего чеков» = total сервера, «Выручка/Прибыль/Средний чек (стр.)» = 20 строк текущей страницы; пометка «(стр.)» 10 px не спасает — владелец читает как итог за период. Нужен серверный агрегат или убрать плитки.
- P1 — фильтры (страница, поиск, мастер, период, режим Документы/Корзина) не в URL; `?masterId` читается один раз.
- P1 — денежные колонки Скидка/Выручка/Прибыль без `text-right`; нет `tfoot`, хотя `pageRevenue` уже посчитан.
- P1 — `md:max-h-[calc(100vh-12rem)]` захардкоживает высоту шапки оболочки и даёт второй скролл внутри `<main>` (сломается при любом изменении верхней панели; в новой оболочке шапка 56 px вместо 64).
- P1 — «Документы склада» / «Корзина» меняют весь контент, но оформлены мелкими чипами внутри карточки фильтров; без `aria-pressed`/`role="tab"` → `Tabs`.
- P1 — блок «Складские операции» рендерится над таблицей чеков даже в режиме «Чеки» — до 5 полноширинных цветных карточек в 9 палитрах.
- P1 — в строке таблицы три высоты контролов (28 / 34 / 42 px); время, госномер, пробег — `text-gray-400`.
- P2 — `window.confirm` ×2; одно состояние чека кодируется трижды (заливка строки + бейдж 9 px + колонка «Статус»); удаление `text-gray-300` (невидимо до hover), 28 px; select «Все мастера» без label; пагинация только Назад/Вперёд при 20 строках.

### 2.3 Касса (`CheckCreatePage.tsx`, 2526 строк) — фаза B / G1

- P1 — режим правки без loading/error: до прихода данных видна пустая форма, при 404/500 — навсегда; строки, добавленные во время загрузки, перезаписываются гидрацией.
- P1 — `max-w-3xl` (768 px) одной колонкой на 1920 px: заказ из 5 строк = 3 экрана скролла. Десктопу нужна двухколоночная раскладка: строки слева, клиент/оплата/итог справа (sticky).
- P1 — пикер товаров — полноэкранный `fixed inset-0 z-[9999]` через portal: прячет оболочку, нет Escape и возврата фокуса, кнопка закрытия без aria-label; 4-колоночная сетка картинок для 1000+ SKU медленнее плотного списка → `Drawer` + `DataTable`.
- P1 — услуга выбирается нативным `<select>` со всеми услугами без поиска; мастер — второй select в каждой строке. Самый медленный шаг кассира на десктопе.
- P1 — свой `formatCurrency` («1 250,5 ₽») против shared `formatMoney` в журнале; сумма на кнопке «Пробить чек» форматируется иначе, чем потом в журнале → `Money`.
- P1 — удалить строку / ± — icon-only без aria-label, hit-area 22 px; способ оплаты — 5 плиток в 5 hue без `role="radiogroup"` → `RadioGroup`/`SegmentedControl`; денежные поля `type="number"`.
- P1 — защита от потери чека только pushState-ловушкой; «Назад», «Отмена» и клик по меню уходят без подтверждения.
- P2 — скевоморфная «квитанция» (тёмная шапка, uppercase, пунктиры, моноширинные итоги); label без `htmlFor`; выпадашка по госномеру без listbox/стрелок; «...» вместо «…» ×5; `transition-all` ×5.

## 3. Что ломается внутри новой оболочки (проверить в фазе B)

- `md:max-h-[calc(100vh-12rem)]` (Журнал ×2), `md:max-h-[70vh]` (Клиенты) — вложенный скролл считает высоту старой шапки; перейти на `DataTable maxHeight` или убрать.
- `sticky bottom-20 md:bottom-0 -mx-4` (панель выбора на Складе) — отрицательные поля под старые паддинги `<main>`.
- Собственные контейнеры `max-w-3xl` (Касса), `max-w-2xl` (Настройки) — третья и четвёртая ширина контента; решение — общий контейнер оболочки, страницы не задают свою ширину (кроме форм-страниц: `max-w-3xl` допустим только для одноколоночных форм).
- Полноэкранный `fixed inset-0 z-[9999]` пикер товаров и ручные «Назад» на `navigate(-1)` (Касса, Настройки) — перевести на `Drawer` и `PageHeader backTo`.
- Ручные крошки/заголовки, повторяющие крошку оболочки («Чеки» под крошкой «Журнал») — H1 должен совпадать с пунктом меню.

## 4. Порядок действий для фазы B (по убыванию отдачи)

1. Каждый запрос страницы — через `QueryState`/`DataTable` с `isError`+`refetch` (закрывает S2, четыре P0).
2. `PageHeader` → `Toolbar` → контент; фильтры и период — в URL (`useSearchParams`), высоты контролов 36 px (S1, S3).
3. Таблицы → `DataTable` (числа справа, `tabular-nums`, `tfoot`, sticky, sort) (S4).
4. Контраст и кегль: `text-gray-400` на содержательном → `text-ink-3`; `text-[9px]/[10px]` → `text-2xs` (S5).
