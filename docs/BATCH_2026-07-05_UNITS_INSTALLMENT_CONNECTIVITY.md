# Пакет 05.07.2026: способ оплаты погашений · дробное количество/единицы · ложный офлайн

Три запроса владельца одним батчем. Гейты зелёные во всех подпроектах; миграции 119/120
прогнаны трижды на чистом PostgreSQL 16 (идемпотентность подтверждена прогоном, не глазами).

## 1. Погашения рассрочки: нал/карта и «у кого деньги на руках»

Проблема: мастер принял погашение наличными — владелец нигде не видел, что деньги у него.
Способ оплаты не записывался вовсе; касса мастера погашения не учитывала; при фильтре по
мастеру погашение приписывалось мастеру исходного чека, а не принявшему.

- Миграция 119: `installment_payments.payment_method` ('cash'|'card', старые строки → 'cash'
  — решение владельца).
- «Принять платёж» (мобилка `InstallmentPayModal`, деталка плана, web `InstallmentsPage`):
  переключатель «Наличными / Картой», дефолт наличные.
- Касса мастера «сегодня»: + погашения, принятые этим пользователем (по `created_by`),
  наличная часть в today_cash, карточная в today_card.
- Движение денег / дашборд: `installmentPaidCash`/`installmentPaidCard` (опциональные),
  подпись «в т.ч. наличными X · картой Y»; атрибуция по принявшему
  (`COALESCE(created_by, master_id чека)`).
- Оборот по-прежнему НЕ растёт от погашений (иначе двойной счёт).

## 2. Дробное количество и единицы измерения (0.5 м шланга)

- Миграция 120: quantity-колонки товарных потоков → NUMERIC(12,3)/(14,3)
  (products.stock/min_stock, stock_movements, check_product_lines, delivery_items,
  purchase_order_items, motivation_accruals.qty); `products.unit`: дефолт 'pcs'→'шт' +
  конвертация legacy-кодов ('pcs','pc','m','l','kg' → 'шт','шт','м','л','кг');
  `SET LOCAL row_security = off` перед UPDATE (fail-loud под RLS). Услуги остаются целыми
  (колонка INT, DTO — «введите целое число»).
- Единицы-пресеты: шт / м / кг / л / уп / компл — чипсы в карточке товара (мобилка + web).
- Ввод количества: компонент QtyInput (мобилка и web) — черновик текста, запятая→точка,
  дробь разрешена всегда, минимум 0.001, округление до 3 знаков, blur-нормализация.
  Прежний контролируемый input физически съедал «0.5» (и на web мог тихо оставить строку
  на ~0 ₽ — устранено).
- Вся арифметика количества (степперы ±, комплекты) — через `roundQty` (float-грязь
  1.3−1=0.30000000000000004 отвергалась бэкендом 400-кой).
- Отображение: «0.5 м × 1 200 ₽», хвостовые нули режутся; единица показывается только
  когда пришла из API (free-text строки без единицы).

## 3. Ложный офлайн под VPN и в «жёсткие окна»

Диагноз: `onlineManager` питался `NetInfo.isInternetReachable`, чья системная проба ходит
на clients3.google.com — в жёсткие окна Google зарезан, под VPN проба мигает → приложение
считало себя офлайн, React Query ставил ВСЕ запросы на паузу («не грузит», «нет сети»),
хотя сервер жив (проверено: с зарубежного IP отвечает 200 — бэкенд не блокирует).

- Пауза запросов теперь ТОЛЬКО при `isConnected === false` (авиарежим/нет линка);
  `isInternetReachable` не влияет. NetInfo.configure переведён на ya.ru (чтобы системная
  проба не долбила Google), вердикт её игнорируется.
- Captive-Wi-Fi закрыт другими рубежами: HTML-страж `isHtmlApiPayload` в axios,
  `backendRecovery.probeHealth` (страж добавлен — портальная 200-страница больше не
  «оздоравливает» бэкенд), нейтральные пробы баннера ужесточены (ya.ru — не-HTML,
  gstatic — строго 204, apple — тело «Success»).
- Таймауты под VPN-латентность: проба API 4→8 с, нейтральные 3→6 с, axios дефолт 12→15 с.

   (если сеть реально жива).
