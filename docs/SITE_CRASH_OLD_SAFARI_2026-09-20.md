# autexa.pw: «Произошла ошибка — Invalid qualified name: 'scaleX,scaleY'»

Дата: 2026-09-20. Ветка: `refactor/full-audit-2026`.
Повод: владелец прислал скриншот с iPhone — вместо сайта карточка ошибки; жалоба «не у всех открывается».

---

## 1. Корневая причина

`frontend/src/pages/landing/sections/Roles.tsx` (секция «Кому подходит Autexa»), мобильная ветка
`matchMedia('(max-width: 767px) and (prefers-reduced-motion: no-preference)')`:

```js
const setters = cells.map((c) => ({ s: gsap.quickSetter(c, 'scale'), … }));
…
update();   // синхронно, внутри useGSAP
```

Цепочка отказа, проверена по исходникам gsap 3.15.0 и воспроизведена механически:

1. `gsap-core.js:4165` — `quickSetter` сам резолвит алиасы CSSPlugin **без проверки на запятую**:
   `p = cache.harness && (cache.harness.aliases || {})[property] || property`.
   Карта алиасов (`CSSPlugin.js:33`) содержит `scale: "scaleX,scaleY"` → `p` становится строкой `"scaleX,scaleY"`.
2. `CSSPlugin.getSetter` (`CSSPlugin.js:1562`) получает имя, в котором запятая уже есть, поэтому его
   собственная защита `p.indexOf(",") < 0 && (property = p)` — холостая, и все ветки проваливаются:
   нет в `_transformProps` → нет в `style` → нет дефиса → `_getSetter`.
3. `_getSetter` (`gsap-core.js:3688`) видит `target["scaleX,scaleY"] === undefined` и наличие `setAttribute`
   → отдаёт `_setterAttribute` (`gsap-core.js:3684`).
4. Итог: `el.setAttribute("scaleX,scaleY", v)`.

`update()` вызывается синхронно внутри `useGSAP`, то есть в `useLayoutEffect`. Исключение оттуда всплывает
в React; единственный `ErrorBoundary` стоит в корне (`main.tsx`), поэтому падала **не секция, а весь сайт** —
ровно то, что на скриншоте: карточка ошибки без шапки и футера.

## 2. Кто именно был затронут — важная поправка

Первичная гипотеза «ломается у всех с телефона» **неверна**. Проверено в реальных движках:

| Движок                                                                    | `setAttribute('scaleX,scaleY', v)`              | Что видит человек                                                                                                    |
| ------------------------------------------------------------------------- | ----------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| WebKit 26.6 (Safari 26 / iOS 26)                                          | принимает, не кидает                            | сайт открывается; эмфаза карточек **не масштабирует** (`transform: none`), на узлах мусорный атрибут `scalex,scaley` |
| Chromium 153                                                              | принимает, не кидает                            | то же самое                                                                                                          |
| Старый WebKit (до ослабления валидации имени атрибута в спецификации DOM) | `InvalidCharacterError: Invalid qualified name` | **весь сайт заменён экраном ошибки**                                                                                 |

Формулировка `Invalid qualified name` — это сообщение старого WebKit, который ещё сверяет имя атрибута
с XML-продукцией `Name`. Значит, автор скриншота сидит на старом iOS.

Точную версию-границу зафиксировать не удалось: Playwright поставляет только актуальный WebKit,
Safari 15–17 в этом окружении недоступен. Это честное ограничение проверки.

Сужающие условия остаются прежними: только ширина < 768 px и только при выключенном «Уменьшении движения».

## 3. Что ещё нашлось попутно

Аудит фронта (4 независимых среза + состязательная проверка каждой находки) подтвердил ещё шесть дефектов,
две из которых — самостоятельные причины «сайт не открывается»:

| #   | Файл                    | Дефект                                                                                                                                                                                      | Кого касается                                                                                     |
| --- | ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| 1   | `main.tsx`              | три guard'а автоперезагрузки стирались на каждом `load` — то есть той самой перезагрузкой, от которой защищали → **бесконечный цикл перезагрузок** на любом детерминированно падающем чанке | все, у кого чанк падает стабильно: вкладка, открытая через деплой; прокси, режущий `/assets/*.js` |
| 2   | `MarkdownView.tsx`      | `remark-gfm` тянет regex-литерал с lookbehind → **ошибка разбора** всего чанка «Базы знаний»                                                                                                | iOS/iPadOS 15.0–16.3; iPhone 6s/7/SE1 заперты на 15.8 навсегда                                    |
| 3   | `FeatureDetailPage.tsx` | `/f/a → /f/b` переиспользует те же DOM-узлы; на них остаётся `visibility:hidden` от `useReveal` предыдущей страницы                                                                         | все, кто ходит между разделами, не докрутив страницу до конца                                     |
| 4   | `OptionalImage.tsx`     | 5 из 17 иллюстраций отдают 404; слот схлопывается **после** замера ScrollTrigger → мёртвая полоса неproявляющегося контента ниже                                                            | посетители `/f/postavshchiki`, `/f/pribyl`, `/f/prochee`, `/f/sotrudniki`, `/f/zhurnal`           |
| 5   | `SectionsSheet.tsx`     | `max-h-[85dvh]` без фолбэка: где `dvh` не поддержан, `max-height` становится `none`, шторка уезжает за верх экрана вместе с крестиком, панель перекрывает и скрим — закрыть нечем           | Chrome < 108, Safari < 15.4, Firefox < 101                                                        |
| 6   | `BroadcastsView.tsx`    | голый `crypto.randomUUID()` в теле компонента                                                                                                                                               | iOS < 15.4 и **любой** не-secure origin (http://, голый IP)                                       |

## 4. Решения

- **`Roles.tsx`** — `quickSetter` на `scaleX` и `scaleY` по отдельности (настоящие transform-props без алиаса,
  дают `_setterTransformWithRender`). Первый синхронный `update()` обёрнут в try/catch: эмфаза декоративная и
  не имеет права класть страницу. Там же починен `quickTo(card, 'scale')` в pointer-tilt — `resetTo()` не
  находил PropTween с именем `scale` (CSSPlugin разложил его на `scaleX`+`scaleY`), поэтому карточка не
  масштабировалась, а gsap писал «scale not eligible for reset» на **каждый** mousemove.
- **`main.tsx`** — сброс guard'ов отложен на 10 с после `load`. Смысл сохранён (позже в той же вкладке другая
  ошибка чанка снова имеет право на одну перезагрузку), цикл разорван: повторное падение происходит через
  ~0.5 с, когда отметка ещё жива.
- **`MarkdownView.tsx` → + `MarkdownViewRich.tsx`** — тяжёлый рендер вынесен в отдельный чанк под `React.lazy`
  и **локальной** границей ошибок. Глобальный `ErrorBoundary` намеренно не переиспользован: он на chunk-ошибке
  перезагружает страницу, а на старом Safari чанк не соберётся и со второго раза.
- **`FeatureDetailPage.tsx`** — `key={section.slug}` на корневом `<div>`. Ключ именно на корне, а не на `<main>`:
  `<Footer />` лежит вне `<main>` и тоже использует `useReveal`, при более узком ключе он унёс бы с собой
  ту же поломку в более редком виде.
- **`OptionalImage.tsx`** — `useLayoutEffect` пересчитывает триггеры при смене состояния слота.
- **`SectionsSheet.tsx`** — `max-h-[85vh]` в классе + инлайновый `maxHeight: '85dvh'`.
- **`utils/uuid.ts`** (новый) — `newUuid()` с корректным v4-фолбэком; используется и в `BroadcastsView`,
  и в `CheckCreatePage` (бэкенд требует hex-UUID форму, иначе 400).

## 5. Регрессия, найденная состязательным ревью правок

Первая версия фикса `OptionalImage` звала `refreshTriggers()` → `ScrollTrigger.refresh()` **без аргумента**.
Это `_refreshAll(true)`: форсированный замер в обход собственной защиты «не мерить во время скролла», который
прогоняет все скроллеры через `scrollTo(0)` и обратно. `FeatureDetailPage` при смене раздела запускает
плавную прокрутку наверх — 404 картинки прилетал в её середину и обрывал её (по CSSOM-View `behavior:'auto'`
отменяет идущую плавную прокрутку), оставляя читателя посреди статьи.

Исправлено: добавлен `refreshTriggersSoon()` — `ScrollTrigger.refresh(true)` → `_onResize(true)` →
`_resizeDelay.restart(true)`, отложенный на 0.2 с вызов `_refreshAll` **без** force, который штатно
откладывается до `scrollEnd`, пока страница скроллится.

## 6. Что проверено и что нет

Проверено:

- `npm run typecheck` — чисто; `npm run lint` — 0 ошибок (684 предсуществующих warning'а); `npm run build` — собирается.
- Изоляция `remark-gfm` подтверждена по собранным чанкам: lookbehind остался **только** в `MarkdownViewRich-*.js`,
  чанк «Базы знаний» похудел с 225 КБ до 71 КБ.
- Механика падения воспроизведена в jsdom + в реальных WebKit 26.6 и Chromium 153; поведение живого
  autexa.pw снято на 8 публичных маршрутах, в двух движках, на 390×844 и 1440×900, с анимацией и с Reduce Motion.
- Все правки прошли состязательное ревью в 4 среза; найдена и исправлена 1 регрессия (раздел 5), 11 претензий отклонены.

НЕ проверено (честные ограничения):

- **Нет реального старого iPhone / Safari 15–17.** Само падение на старом WebKit подтверждено только логикой
  и сообщением об ошибке на скриншоте владельца, не прогоном на устройстве.
- Ручной приёмки на физическом устройстве не было вообще — см. чек-лист ниже.
- Фикс **не задеплоен**.

## 7. Чек-лист ручной приёмки

С телефона (Reduce Motion выключен):

1. Открыть `autexa.pw` — сайт открывается, карточки ошибки нет.
2. Секция «Кому подходит Autexa»: протащить карусель — карточка у центра **заметно крупнее** соседних
   (раньше менялась только прозрачность).
3. Открыть любой раздел → внизу «Разделы» → выбрать другой раздел. Заголовки и карточки новой страницы
   **видны**; прокрутка наверх плавная и не обрывается.
4. Разделы «Поставщики», «Прибыль», «Прочее», «Сотрудники», «Журнал» — текст ниже шапки проявляется, мёртвой полосы нет.
5. «Разделы» на узком экране — шторка не выше ~85 % экрана, крестик виден, список скроллится.

С десктопа: навести мышь на карточку персоны — карточка наклоняется **и чуть увеличивается**; в консоли
нет «scale not eligible for reset».

Багом считается: любой экран «Произошла ошибка», любой невидимый текст, любая страница, которая
перезагружается сама больше одного раза подряд.

## 8. Открытые вопросы к владельцу

1. **5 отсутствующих иллюстраций.** `public/img/landing/` содержит 12 файлов, `content.ts` объявляет 17 разделов.
   Нет: `f-postavshchiki.webp`, `f-pribyl.webp`, `f-prochee.webp`, `f-sotrudniki.webp`, `f-zhurnal.webp`.
   Код к их отсутствию устойчив, но слоты пустые. Файлы — контент, их кладёт владелец.
2. **Sentry.** Фронт в Sentry не пишет вообще (`@sentry/*` есть только в `backend/` и `mobile/`), поэтому
   уведомления, о которых спрашивал владелец, к этому падению отношения не имеют. Для разбора нужен
   auth-токен с `event:read`, `project:read`, `org:read`.
3. **Экранированный юникод в комментариях.** В четырёх файлах комментарии лежат как литералы `\uXXXX`
   (`frontend/src/pages/{SuppliersPage,CheckCreatePage}.tsx`, `backend/src/products/products.controller.ts`,
   `mobile/src/screens/ProductsScreen.tsx`). Предсуществующее, на работу не влияет, не трогал.
