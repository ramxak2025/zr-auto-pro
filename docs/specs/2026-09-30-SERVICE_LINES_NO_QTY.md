# Услуги в Кассе без количества (правка №4, 2026-09-30)

**Запрос владельца.** «В кассе, где услуги, убрать количество, оставив только цену — чтобы
статистика по услугам потом корректно считалась». Товары количество сохраняют.

**Решение владельца (30.09):** историю не трогать — старые строки с количеством 2–3 остаются
как есть; в статистике каждая строка услуги = одна услуга.

**Что есть в коде (разведка 2026-09-30).** `check_service_lines.quantity INT DEFAULT 1`
(`001_init.sql:152-161`), nullable, без CHECK; `total = price × quantity`, зарплата мастера
печётся в `salary_amount` от `total` (`checks.service.ts:2974-2991`). Количество > 1 сегодня
создают: поле «Кол.» в мобильной Кассе (`CheckCreateScreen.tsx:3944-3960`), степпер и
«повторное добавление = +1» в мобильном редакторе шаблонов (`TemplateEditorScreen.tsx:167-177, 526`),
применение таких шаблонов на вебе и в мобилке. Веб ввода количества не имеет, но показывает
«× N» в Кассе (`CheckCreatePage.tsx:1660-1665`) и колонку «Кол-во» в деталях
(`CheckDetailPage.tsx:318`) — это вернул редизайн 25.09, хотя коммит `0effa7ff` (февраль) их
уже убирал. **Статистика считает по-разному:** отчёт «По услугам» и «Топ-5 услуг» — `SUM(quantity)`
(`services.builder.ts:45,49,109`, `summary.builder.ts:313`), «мастерство» в карточке
сотрудника — `COUNT(*)` строк (`employees.service.ts:688-708`). Одна строка «×3» в отчёте —
это 3 работы и заниженная «Средняя цена».

## 0. Правила

- Строка услуги = одна услуга по одной цене. В новых чеках и шаблонах `quantity` всегда 1.
- Одна и та же услуга дважды — две строки (так уже работает добавление в Кассе).
- Сервер **продолжает принимать** `quantity` в `CheckServiceLineDto` (старые версии
  приложения ещё шлют его и показывают клиенту `price × qty`; ломать их суммы нельзя).
  Ужесточение DTO — после того, как все обновятся, отдельной правкой.
- Статистика по услугам считает **строки**, а не `SUM(quantity)`. Старая строка «×3» —
  одна услуга с выручкой её `total`.
- Legacy-строки с `quantity > 1` в старых чеках показываются честно: «Мойка ×3» в названии
  строки, сумма — как в чеке. Ни миграций, ни правок данных.

## 1. Backend (`backend-engineer`)

1. **Отчёт «По услугам»** (`reports/builder/builders/services.builder.ts:25-58`):
   `qty` → число строк услуги, не возвращённых полностью
   (`COUNT(*) FILTER (WHERE COALESCE(r.qty,0) < COALESCE(l.quantity,1))`); `revenue` — как
   сейчас (`total − возвраты`); `avgPrice = revenue / qty`; KPI «Работ выполнено» = Σ qty;
   колонка «Количество» → «Оказано» (число). Сноски L116-120: «Количество — число оказанных
   услуг (строк заказ-наряда); средняя цена = выручка ÷ количество».
2. **«Сводный» → «Топ-5 услуг»** (`summary.builder.ts:308-337`): `COUNT(*)` строк с тем же
   исключением полностью возвращённых (сейчас возвраты там не вычитаются — выровнять с
   «По услугам»). Колонка «Кол-во» → «Оказано».
3. `employees.service.ts:688-708` («мастерство») уже `COUNT(*)` — не трогать.
4. Шаблоны (`check-templates.controller.ts:50,59`, тело `any`): валидировать
   `services[]` DTO-классом (`serviceId?`, `name`, `price ≥ 0`); поле `quantity`, если
   пришло, **принимать и сохранять как 1** (шаблон — новая сущность, старых клиентов с
   суммами он не ломает). Старые шаблоны с `quantity > 1` в БД не правятся — клиенты
   разворачивают их в строки при загрузке (§2).
5. `shared/reports/catalog.ts:128-137` — текст метода отчёта «По услугам».
6. Фискальный чек (`fiscal.service.ts:238-279`), возвраты (`returns.service.ts:233-257`),
   PDF — без изменений на сервере: читают `quantity` из БД (у legacy-строк он честный).

## 2. Shared

- `shared/utils/checkLines.ts`: `expandServiceQuantities(lines)` — строку с `quantity > 1`
  разворачивает в N строк с `quantity: 1`, `total: price` (для применения старых шаблонов и
  их открытия в редакторе); `serviceLineTotal(line) = round2(price × (quantity ?? 1))` (для
  legacy-строк в режиме редактирования). Тест `mobile/src/utils/__tests__/checkLines.test.ts`.
- `CheckServiceLine.quantity` остаётся в типе (`shared/types/index.ts:1662-1671`) —
  комментарий «всегда 1 у новых строк; >1 только у старых чеков».
- `CreateCheckRequest.services[].quantity` — сделать необязательным (`quantity?: number`),
  клиенты его не шлют.

**Уточнено в фазе 0 (контракт зафиксирован в `shared/`; при расхождении с текстом выше приоритет у этого списка):**

- `services[].quantity?` необязателен **и в `CreateCheckRequest`, и в `UpdateCheckRequest`**. При
  редактировании чека клиент шлёт `quantity` только у legacy-строки, у которой оно было `> 1`
  (значение не меняется); у новых строк поле не передаётся.
- Тело `POST/PUT /check-templates` описано отдельным типом `CheckTemplateServiceInput`
  (`shared/api/types.ts`): `{ serviceId?, name, price, quantity? }`. `checkTemplatesApi.create` и
  `update` принимают `services: CheckTemplateServiceInput[]`; новые клиенты `quantity` не шлют, сервер
  поле принимает и сохраняет как `1` (§1.4).
- Тип **ответа** `CheckTemplate.services[].quantity` остаётся `number` (у новых шаблонов `1`, у старых
  бывает больше `1`) — клиенты применяют `expandServiceQuantities` при загрузке и открытии в редакторе.
  Комментарий об этом добавлен над `CheckTemplate.services` в `shared/types/index.ts`.
- `expandServiceQuantities` разворачивает строку, только если `quantity` — целое от `2` до
  `MAX_EXPANDED_QUANTITY = 100`. Строки с `quantity > 100` и дробным `quantity` остаются legacy-строкой
  как есть (иначе одна опечатка в шаблоне даёт тысячи строк в редакторе), у таких строк клиент
  показывает «×N» и считает сумму `serviceLineTotal`. `total` у копий пересчитывается как
  `round2(price)`; строка без `total` (шаблон) остаётся без `total`.
- `serviceLineTotal(line) = round2(price × (quantity ?? 1))` — `?? 1`, тогда как сервер считает
  `price × (quantity || 1)`; результаты расходятся только при `quantity = 0`, которого нормальные
  данные не содержат (для `0` клиент получит `0`, сервер посчитает как `1`).
- `shared/reports/catalog.ts`: метод «По услугам» обновлён; метод «Сводного» не менялся (в нём про
  количество услуг ничего нет).
