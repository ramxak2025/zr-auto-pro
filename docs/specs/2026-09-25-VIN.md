# VIN-код автомобиля (правка №2, 2026-09-25)

**Запрос владельца.** В приложении и на сайте к автомобилю можно добавить VIN, и по нему
марка и модель записываются сами. Опция включается в настройках компании, по умолчанию
выключена. При включённой опции работает поиск клиента по VIN; при выключенной — всё,
что связано с VIN, скрыто. Платный источник расшифровки — по ключу самого клиента,
Autexa за запросы не платит.

Контракт уже зафиксирован в коде — он первичен, документ его поясняет:

- `shared/types/index.ts` — секция «VIN (171)»: `VinDecodeResult`, `VinProviderInfo`,
  `VinSettings`, `UpdateVinSettingsRequest`, `CarLookupResult`, `Tenant.vinEnabled`.
- `shared/api/types.ts` — `CreateCarRequest.vin`, `UpdateCarRequest.vin`.
- `shared/api/createServices.ts` — `createVinApi` (`decode`, `getSettings`, `updateSettings`),
  `createCarsApi().lookupByVin`.
- `shared/utils/vin.ts` — `normalizeVin`, `isValidVin`, `vinCheckDigitOk`, `vinNeedsCheckDigit`,
  `vinModelYear`, `formatVin`, `vinWmi`. Backend не импортирует `shared/` — копия логики
  живёт в `backend/src/vin/vin.util.ts` и обязана совпадать байт-в-байт по поведению.

## 1. Данные (backend)

Миграция `171_cars_vin.sql` (идемпотентная):

- `cars.vin TEXT NULL` — хранится ТОЛЬКО нормализованный VIN (17 символов, латиница,
  верхний регистр). Индекс `idx_cars_tenant_vin ON cars(tenant_id, vin) WHERE vin IS NOT NULL`.
  Уникальность НЕ на уровне БД (история/смена владельца) — проверяет сервис: другой
  автомобиль тенанта с тем же VIN → `409 { code: 'VIN_DUPLICATE', carId, clientId, clientName,
message: 'Автомобиль с таким VIN уже есть у клиента <Имя>' }`.
- `tenants.vin_enabled BOOLEAN NOT NULL DEFAULT false`.
- `tenants.vin_decoder_provider TEXT NULL`, `tenants.vin_decoder_credentials JSONB NULL`
  (учётные данные платного сервиса; наружу никогда не отдаются, только `hasCredentials`).
  Если в проекте уже есть хелпер шифрования секретов интеграций (Mango / «Мои Звонки» /
  эквайринг) — использовать его; если нет — хранить как соседние интеграции хранят свои ключи.

## 2. Backend-модуль `backend/src/vin/`

- `vin.module.ts`, `vin.controller.ts` (префикс `vin`), `vin.service.ts`, `vin.util.ts`,
  `wmi-table.ts`, `providers/` (адаптеры).
- `POST /vin/decode { vin }` — любая роль тенанта. Нормализовать; если `!isValidVin` →
  `200 { valid:false, source:'none', make:null, … }` (НЕ 400). Иначе источники по очереди,
  первый давший марку побеждает, **модель берём лучшую из доступных**:
  1. платный провайдер тенанта (если `provider` и `credentials` заданы). Таймаут 6 с.
     Ошибка/пусто → запись в `notes` («Платный сервис не ответил — использованы бесплатные
     источники») и дальше;
  2. NHTSA vPIC `GET https://vpic.nhtsa.dot.gov/api/vehicles/DecodeVinValues/{vin}?format=json`
     → `Make`, `Model`, `ModelYear`, `BodyClass`, `FuelTypePrimary`, `DisplacementL`.
     Таймаут 4 с, любая ошибка — молча дальше. Марку приводить к человеческому виду
     («TOYOTA» → «Toyota», «BMW» остаётся «BMW», «LAND ROVER» → «Land Rover»);
  3. офлайн-таблица WMI (`wmi-table.ts`): первые 3 символа → производитель/марка. Таблица
     должна покрывать рынок РФ: АвтоВАЗ/Lada (XTA), ГАЗ (X96, XTH), УАЗ (XTT), КАМАЗ (XTC),
     российская сборка иномарок (X7L Renault, Z8N Nissan, XW8 VW Калуга, XWE Kia/Автотор,
     X4X BMW Автотор, Z94 Hyundai СПб, XUU GM-АвтоВАЗ, X9F Ford, XW7 Toyota СПб, X8… и др.),
     китайские бренды (Chery, Haval, Geely, Changan, Exeed, Omoda, JAC, GAC, Tank, Li Auto,
     Zeekr, BYD, Jetour, Kaiyi, Dongfeng, FAW, Voyah, Hongqi…), Корея, Япония, Европа, США.
     Ориентир — ≥ 300 записей, источник — список WMI в Википедии (WebFetch разрешён).
     Год — `vinModelYear`. `source:'wmi'`, `model:null`.
     Итог: `makeModel = [make, model].filter(Boolean).join(' ') || null`.
     Кэш результата в памяти 24 ч по нормализованному VIN (расшифровка неизменна).
     Rate-limit: не более 60 расшифровок/мин на тенанта (общий RateLimitGuard уже стоит —
     достаточно, если он покрывает; иначе простой счётчик в сервисе).
- `GET /vin/settings` и `PATCH /vin/settings` — ключ `company_manage` (тот же гейт, что
  у `PATCH /my-company`). `providers` — список из реестра адаптеров.
- **Платные провайдеры.** Интерфейс адаптера: `{ id, name, description, site, fields,
decode(vin, credentials): Promise<Partial<VinDecodeResult> | null> }`. Первый адаптер —
  тот сервис, у которого агент ПОДТВЕРДИТ по документации самостоятельное получение ключа
  API с оплатой за запросы (кандидаты: Vincario/vindecoder.eu — ключ + секрет, хорошо знает
  европейские VIN; российские Автокод/Автотека — если есть публичный API без договора).
  Итог проверки записать в `docs/specs/2026-09-25-VIN.md` → раздел «Провайдеры» (дописать).
  Без реального ключа адаптер проверяется на подставном ответе (unit-тест с моком fetch).

## 3. Изменения существующих модулей (backend)

- `cars`: `vin` в create/update (принимать только при `vin_enabled` тенанта; при выключенной
  опции поле молча игнорировать), в ответах `Car.vin`, в `GET /cars?search=` — совпадение по
  VIN (полное или подстрока ≥ 4 символов, регистронезависимо, после `normalizeVin`) только при
  включённой опции; `GET /cars/lookup-by-vin?vin=` → `CarLookupResult | null` (некорректный
  VIN → `null`, не 400). При очистке (`vin: null | ''`) — `NULL`.
- `clients`: `GET /clients?search=` при включённой опции дополнительно ищет по VIN машин
  клиента (как сейчас по госномеру). Мобильный/веб поиск клиента в Кассе идёт через
  существующие методы (`lookupByPhone`, `lookupByPlate`, список клиентов) — для VIN
  используем `lookupByVin` + общий `search`.
- `tenants` / `auth`: `vinEnabled` в `GET /my-company` и во ВСЕХ проекциях `User.tenant`
  (`/auth/login`, `/auth/me`, `/auth/refresh` если есть) — так же, как сейчас едет `timezone`.
- Импорт из Excel (`imports`): колонка «VIN» распознаётся и пишется, если опция включена.
  P2, делать в конце.
- PDF заказ-наряда: VIN под маркой/моделью, если есть. P2.

## 4. Клиенты (web и mobile) — поведение

Признак: `user.tenant.vinEnabled === true` (хук `useVinEnabled()` в обоих клиентах; в
mobile — рядом с `useTenantTimezone`). Пока опция выключена — НИ ОДНОГО упоминания VIN в UI.

1. **Настройки компании → блок «Автомобили»**: переключатель «VIN-код автомобиля» с
   описанием «Поле VIN у машины, автоматическое определение марки и модели, поиск клиента
   по VIN». Под ним (только когда включено): «Источник данных» — «Бесплатные справочники»
   (по умолчанию) или один из `providers`; при выборе провайдера — его `fields`
   (секреты — поле пароля, значение не показывается; состояние «Ключ сохранён · Заменить ·
   Удалить»), ссылка `site` «Где получить ключ». Кнопка «Проверить» — вызывает `decode` с
   тестовым VIN `WBA3A5C55CF123456`? Нет: с VIN, который пользователь вводит в поле
   «Проверить на VIN…» (по умолчанию пусто) — показывает результат и `source`.
2. **Форма автомобиля** (создание/редактирование везде: карточка клиента, список авто,
   быстрое создание в Кассе): поле «VIN» под маркой/моделью. Компонент `VinInput`:
   верхний регистр, кириллица → латиница, только допустимые символы, счётчик `12/17`,
   моноширинный текст, группировка `WMI VDS VIS` в отображении; при 17 валидных символах
   (debounce 400 мс) — `vinApi.decode` → если марка/модель пусты, подставить `makeModel`
   молча; если заполнены — показать чип «По VIN: Kia Rio · Заменить». Подпись-источник:
   «Определено по VIN» / «Марка по справочнику, модель допишите». Ошибка 409 VIN_DUPLICATE —
   понятное сообщение с именем клиента.
3. **Карточки и списки авто**: VIN моноширинным под маркой (web — кнопка «копировать»).
4. **Поиск**: список клиентов — плейсхолдер «Имя, телефон, госномер или VIN»; Касса —
   у переключателя режимов поиска появляется четвёртый сегмент «VIN» (RU · INT · ТЕЛ · VIN);
   ввод VIN → `lookupByVin` → найденная машина+клиент подставляются как при поиске по
   номеру; не найдено → предложение создать клиента с уже заполненным VIN. На узких iPhone
   четыре сегмента должны влезать (сократить подписи или сегменты с иконками — см.
   комментарий в `PlateModeSwitcher.tsx` про SE/mini).
5. Ничего не ломать в режиме «выключено»: снапшот UI без опции должен быть байт-в-байт прежним.
