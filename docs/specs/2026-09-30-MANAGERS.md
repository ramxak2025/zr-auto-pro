# Менеджеры платформы и доля владельца (правка №2, 2026-09-30)

**Запрос владельца.** В кабинете суперадмина владелец создаёт профили своих сотрудников
(«менеджеров»). У менеджера свой кабинет: он создаёт автосервисы, выдаёт пробные доступы,
продлевает платные подписки, меняет тарифы — «делает работу владельца». Деньги за платные
продления менеджер получает от своих клиентов сам; **60 % каждой такой оплаты записываются
как долг менеджера перед владельцем**, 40 % остаются менеджеру. Владелец в своём кабинете
передаёт клиентов (автосервисы) от одного менеджера другому.

**Что есть в коде (разведка 2026-09-30).** Роли: `superadmin | director | admin | master`
(CHECK в `001_init.sql:66`, enum `UserRole` в `shared/types/index.ts:824-829`). Суперадмин —
`role='superadmin' AND users.tenant_id IS NULL`; тенант-less обработка завязана на строку
`'superadmin'` в `auth-cache.ts:63-73` (`isTenantLess`), `tenant-context.interceptor.ts:52`
(admin-пул в обход RLS), `tenant-write-guard.interceptor.ts`, `subscription-guard.interceptor.ts:92-102`,
`roles.guard.ts:23` (bypass). Продления пишутся в `subscription_payments` (миграция 122:
`amount, is_free, period_from, period_to, previous_end, note, created_by`) — это
единственный журнал денег за подписку; связи «тенант → сотрудник платформы» нет. Админские
маршруты — `tenants.controller.ts` (все `@Roles('superadmin')`), веб `frontend/src/pages/admin/*`,
мобилка `mobile/src/screens/admin/*` + `AdminShellNavigator` (в `AppNavigator.tsx:900-912`
выбирается по `role === 'superadmin'`). Дату подписки можно сдвинуть мимо журнала через
`PATCH /tenants/:id { subscriptionEnd }` и при создании тенанта.

## 0. Модель

- **Роль `manager`** («Менеджер»): пользователь без тенанта (`tenant_id IS NULL`), как
  суперадмин, но с доступом только к своим автосервисам. Назначить роль может только
  суперадмин, только при создании через `/admin/managers` (в тенант такую роль назначить нельзя).
- **Принадлежность клиента:** `tenants.manager_id` (NULL = клиент владельца, «без менеджера»).
  Все существующие тенанты остаются без менеджера. Передача — только суперадмином.
- **Доля владельца** — `users.owner_share_percent` у менеджера (по умолчанию **60**, суперадмин
  может задать своё значение каждому менеджеру). При платном продлении, которое проводит
  менеджер, в строку `subscription_payments` пишется снимок: `manager_id`,
  `owner_share_percent`, `owner_share_amount = round(amount × pct / 100, 2)`. Бесплатные
  продления (`is_free`) долю не создают.
- **Если платную оплату проводит суперадмин** для клиента менеджера — по умолчанию доля
  **не начисляется** (деньги пришли владельцу напрямую). В форме продления суперадмина
  появляется галочка «Оплату получил менеджер <Имя> — учесть его долю», тогда снимок пишется
  как при оплате менеджером.
- **Расчёты с менеджером** — `manager_settlements`: суперадмин записывает, сколько менеджер
  передал владельцу (положительная сумма) или корректировку (отрицательная — долг
  менеджера растёт, обязательна причина). **Баланс менеджера** = Σ `owner_share_amount` его
  платежей − Σ `manager_settlements.amount`. Положительный баланс — «менеджер должен».
- При передаче клиента история платежей остаётся за тем менеджером, который их провёл
  (долг уже записан на него). Будущие платежи — за новым.
- Пробный доступ от менеджера ограничен настройкой платформы
  `platform_settings.manager_max_free_days` (по умолчанию 30 дней на одно бесплатное продление).
  Суперадмин меняет её в «Тарифы → Настройки».
- Менеджеру разрешено для своих клиентов: создать автосервис (с владельцем-директором),
  пробный доступ, платное продление, смена тарифа, приостановить/возобновить, «войти как
  владелец», сбросить пароль владельца. Запрещено: удалять автосервис, править реквизиты
  тенанта и дату подписки напрямую (`PATCH /tenants/:id`), видеть чужих клиентов, тарифы
  создавать/менять, рассылки, заявки на регистрацию, журнал действий платформы. Всё, что
  менеджер делает, пишется в `admin_audit_log` с ним как актором.

## 1. Данные (backend) — миграция `173_platform_managers.sql` (идемпотентная)

```sql
-- 1. роль: снять inline-CHECK из 001 (имя найти через pg_constraint по conrelid='users' и
--    contype='c' с 'role' в определении — не полагаться на имя users_role_check) и создать заново
--    CHECK (role IN ('superadmin','director','admin','master','manager'));
ALTER TABLE users ADD COLUMN IF NOT EXISTS owner_share_percent NUMERIC(5,2);   -- только у manager
ALTER TABLE tenants ADD COLUMN IF NOT EXISTS manager_id UUID REFERENCES users(id) ON DELETE SET NULL;
CREATE INDEX IF NOT EXISTS idx_tenants_manager ON tenants (manager_id) WHERE manager_id IS NOT NULL;
ALTER TABLE subscription_payments
  ADD COLUMN IF NOT EXISTS manager_id UUID REFERENCES users(id) ON DELETE SET NULL,
  ADD COLUMN IF NOT EXISTS owner_share_percent NUMERIC(5,2),
  ADD COLUMN IF NOT EXISTS owner_share_amount NUMERIC(10,2),
  ADD COLUMN IF NOT EXISTS plan_id UUID REFERENCES plans(id) ON DELETE SET NULL,
  ADD COLUMN IF NOT EXISTS plan_name TEXT;
CREATE INDEX IF NOT EXISTS idx_subscription_payments_manager ON subscription_payments (manager_id, created_at DESC) WHERE manager_id IS NOT NULL;
CREATE TABLE IF NOT EXISTS manager_settlements (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  manager_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  amount NUMERIC(10,2) NOT NULL CHECK (amount <> 0),
  note TEXT,
  settled_on DATE NOT NULL DEFAULT CURRENT_DATE,
  created_by UUID REFERENCES users(id) ON DELETE SET NULL,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX IF NOT EXISTS idx_manager_settlements_manager ON manager_settlements (manager_id, created_at DESC);
ALTER TABLE platform_settings ADD COLUMN IF NOT EXISTS manager_max_free_days INT NOT NULL DEFAULT 30;
```

`manager_settlements` — глобальная таблица без `tenant_id`, без RLS (как `admin_audit_log`);
доступ к ней только через admin-пул из маршрутов суперадмина и менеджера.
`subscription_payments` остаётся под RLS `tenant_isolation` — читается через admin-пул.

## 2. Backend

### 2.1 Тенант-less роль

Ввести `PLATFORM_ROLES = new Set(['superadmin','manager'])` и `isPlatformRole(role)` в
`common/auth-cache.ts`; использовать вместо строкового сравнения с `'superadmin'` в:
`isTenantLess` (`auth-cache.ts:63-73`), `tenant-write-guard.interceptor.ts`
(`NO_TENANT_CONTEXT` + префикс `manager` в список исключений), `subscription-guard.interceptor.ts`,
`auth.service.ts` (вход без филиалов → `pointId = null`, `select-point`/`switch-point`
недоступны), `jwt.strategy.ts` (`NO_TENANT_ID` sentinel), `account.service.ts` если
затрагивает. **`RolesGuard` bypass (`roles.guard.ts:23`) остаётся только у superadmin** —
менеджер проходит только там, где перечислен явно.

`TenantContextInterceptor` (`tenant-context.interceptor.ts:52`): для `manager` admin-пул
**только** на маршрутах с префиксом `/api/manager/*` и `/api/auth/*`; на всех остальных —
app-пул с nil-tenant (RLS ничего не отдаёт). Так менеджер не получает случайного доступа к
незащищённым чтениям тенантов.

`UsersService.assertCanAssignRole` (`users.service.ts:76-91`): роль `manager` назначается
только суперадмином и только через `AdminManagersService.create` (в `POST /users` с любым
`tenantId` — 400). `effectivePermissionsFor` для `manager` — все права false (как сейчас для
неизвестной роли). `shared/utils/formatters.ts:219-224` — подпись «Менеджер».

**Уточнено в фазе 0 (контракт зафиксирован в `shared/`; при расхождении с таблицами выше приоритет у этого списка):**

- `GET /admin/managers/:id` → `PlatformManagerDetail`: `tenants` — полные `Tenant[]` (та же форма,
  что у `GET /manager/tenants`: со `lastPayment`, `currentPeriodKind`, `userCount`), а не урезанные
  пять полей из таблицы. `POST` и `PATCH /admin/managers` возвращают `PlatformManager`.
- Заметка менеджера хранится в `users.owner_notes` (колонка уже есть); в `PATCH` поле
  `note?: string | null`, `null` или пустая строка очищает.
- Телефон занят (`POST`/`PATCH /admin/managers`) → `409` с телом `{ message, code: 'PHONE_TAKEN' }`
  (`ManagerPhoneTakenError`).
- `GET /manager/tenants?status=` принимает `SubscriptionStatus` (`active | expired | suspended`,
  `suspended` главнее `expired`); фильтр «истекает за 7 дней» клиент делает сам по `subscriptionEnd`.
- `GET /admin/managers/:id/ledger?months=` и `GET /manager/ledger?months=`: окно лент 1..36 месяцев
  (по умолчанию 12), ленты — новые сверху, `balance` — ВСЕГДА за всё время. `payments[]` — только
  платные оплаты этого менеджера со снимком доли, плюс `tenantName`.
- `POST /manager/tenants` (`CreateManagerTenantRequest`): поле `city` **убрано** (у `tenants` такой
  колонки нет, `CreateTenantRequest` его не знает); `note` сохраняется как `subscriptionNote`
  тенанта; `trialDays` не передан ⇒ сервер выдаёт `min(14, maxFreeDays)` дней (менеджер
  бессрочных автосервисов не создаёт: тенант без `subscriptionEnd` был бы бесплатным доступом мимо
  журнала и доли владельца); `trialDays > maxFreeDays` → `400`.
- `POST /manager/tenants/:id/extend` принимает ТОЛЬКО объект с обязательным `type`
  (`'free' | 'paid'`); тело без `type` (старая форма `{ days }`) → `400`. Поле `creditManager` тут
  игнорируется: платные продления менеджера всегда несут долю.
- `POST /manager/tenants/:id/suspend` и `/unsuspend` принимают `{ reason?: string }`
  (`SuspendTenantRequest`); оба действия пишутся в аудит.
- `PATCH /admin/tenants/:tenantId/manager` → `TransferTenantManagerResponse`
  `{ ok: true, tenantId, managerId, managerName }` (`managerName` — `null`, если клиента сняли).
- Аудит-действия (`tenant_create`, `tenant_transfer_manager { from, to }`, `manager_create`,
  `manager_update`, `manager_settlement`, `owner_password_reset`) перечислены в комментарии к
  `AuditLogEntry`. **Общего словаря подписей в `shared/` нет** — подписи живут только в клиентских
  `frontend/src/components/admin/auditActions.ts` и `mobile/src/screens/admin/AdminMoreScreen.tsx`.
