# Записи (appointments) — детальный дизайн

**Дата:** 2026-06-18 (ревизия 2 — по уточнению владельца)
**Статус:** ДИЗАЙН. Owner уточнил: это ВНУТРЕННИЙ инструмент персонала (НЕ публичная запись клиента). Код пишем после утверждения объёма.

Суть: сотрудник (мастер/админ с правом `bookings_access`) заводит запись клиента на дату/время; клиенту опц. уходит SMS/WhatsApp подтверждение + напоминание; когда клиент приехал — «Подтвердить приход» открывает кассу с подставленным клиентом → дальше обычный чек. Никакой публичной страницы/слотов/самозаписи клиента.

---

## 1. Переиспользуем (не изобретаем)

| Нужно                                                | Уже есть                                                               |
| ---------------------------------------------------- | ---------------------------------------------------------------------- |
| Поиск клиента по номеру/телефону + «добавить нового» | Касса (`CheckCreateScreen` client-picker) + `QuickClientCreateSheet`   |
| Открыть кассу с подставленным клиентом               | `CheckCreate` навигация с params (клиент/авто/мастер/коммент)          |
| SMS/WhatsApp клиенту                                 | Messaging-адаптеры Маркетинга (sms/smsru/whatsapp)                     |
| Напоминание за N часов                               | Паттерн `ReminderService` (cron)                                       |
| Пуш-уведомления                                      | `PushService`                                                          |
| Права/видимость                                      | Матрица прав (`bookings_access`) + роль (master=свои, admin/owner=все) |

## 2. Модель данных (новые идемпотентные миграции, хвост 073 → 074/075)

**`bookings`:**

- `id`, `tenant_id`, `client_id` (обязателен — выбран или создан), `car_id` (опц.), `master_id` (на кого запись — см. §9 Q1), `created_by` (кто завёл), `scheduled_at timestamptz` (дата+время), `comment text`, `status` (`scheduled` | `arrived` | `converted` | `cancelled` | `no_show`), `check_id` (когда провели чек по записи), `notify_on_create bool`, `reminder_sent_at timestamptz`, `created_at`, `cancelled_at`, `cancelled_by`.
- Индексы: `(tenant_id, scheduled_at)`, `(tenant_id, master_id, scheduled_at)`, `(tenant_id, status)`, `(tenant_id, client_id)`.

**`booking_settings`** (1 строка/тенант):

- `tenant_id` PK, `notify_client_on_create bool` (слать ли «вы записаны» при создании), `reminder_enabled bool`, `reminder_hours int` (за сколько часов; дефолт 2), `channel` (`auto`|`sms`|`whatsapp` — `auto` = что настроено в Маркетинге).

Тенант-изоляция как везде. Применённые миграции не трогаем.

## 3. Поток создания (сотрудник)

Записи → «+ Новая запись»:

1. **Клиент** — поиск по номеру авто / телефону (тот же компонент, что в кассе). Не нашли → «Добавить клиента» инлайн (QuickClientCreate). Опц. выбор авто клиента.
2. **Мастер** — см. §9 Q1 (мастер создаёт → он сам; админ → выбирает).
3. **Дата/время** — нативный календарь + time picker (iOS красивый).
4. **Комментарий** — свободный текст («установка ГБО», «ТО» и т.п.). Услуги/товары НЕ выбираем.
5. Сохранить → `booking(status=scheduled)`. Если `notify_client_on_create` — клиенту SMS/WhatsApp «Вы записаны на <дата> <время> в <сервис>». Пуш админам/владельцу о новой записи (опц.).

## 4. Списки и видимость

- **Мастер** видит только записи где `master_id = self`. **Админ/владелец** — все записи тенанта (кто, во сколько, к какому мастеру).
- Вкладки: **Предстоящие** (scheduled, по времени) и **Прошедшие** (arrived/converted/cancelled/no_show или scheduled_at в прошлом). В прошедшей записи, если `check_id` есть — строка «Чек №… » с переходом в чек.
- Бейдж новых/сегодняшних записей на иконке раздела.

## 5. Отмена

- Мастер отменяет свою; админ/владелец — любую. `status=cancelled`, `cancelled_at/by`. Опц. SMS клиенту об отмене (позже). Сервер-проверка прав (мастер не может отменить чужую).

## 6. Приход → касса (ключевой UX)

«Подтвердить приход» на записи → навигация в `CheckCreate` с params (clientId, carId, masterId, comment-как-преднаполнение). Мастер добавляет услуги/товары и сохраняет чек как обычно. На успешном сохранении чека: `booking.status=converted`, `booking.check_id=<новый чек>`. Если мастер вышел из кассы не сохранив — запись остаётся `arrived` (можно повторить). Никакой автокассы «вслепую» — просто префилл.

## 7. Напоминания (cron)

Фоновый прогон (как `ReminderService`): раз в ~15 мин ищет `scheduled` записи, у которых `scheduled_at - reminder_hours <= now` и `reminder_sent_at IS NULL` и `reminder_enabled`, шлёт клиенту SMS/WhatsApp «Вы записаны на <время> в <сервис>; если передумали — позвоните, отменить» и ставит `reminder_sent_at`. Идемпотентно (повторно не шлём). Нет провайдера → тихо пропускаем.

## 8. Права

- `bookings_access` — видеть/создавать записи (мастер/админ). Без него раздел скрыт (section-visibility) И API закрыт (PermissionsGuard).
- Видимость «свои/все» — по роли (master=свои), не отдельный тумблер. Отмена чужой — только admin/owner (сервер-проверка).
- Конверсия в чек = обычное право создавать чек.

## 9. Решения владельца (2026-06-18) — зафиксировано

1. **Назначение мастера — `master_id` НУЛЛАБЕЛЬНЫЙ.** Мастер создаёт → `master_id=self` (по умолчанию). Админ/владелец создаёт → может выбрать мастера ИЛИ оставить «без мастера» (общая запись — видят только админ/владелец, пока мастер не назначен). Видимость: мастер видит `master_id=self`; админ/владелец — все.
2. **Конфликты — мягкое предупреждение.** Выбор любого времени; если у выбранного мастера уже есть пересекающаяся запись — показываем «⚠️ у мастера уже есть запись на это время», но НЕ блокируем сохранение.
3. **Канал уведомления** = провайдер, настроенный в Маркетинге (SMS/WhatsApp). Отдельного выбора нет; нет провайдера → запись создаётся без уведомления (тихо).
4. **Напоминание** — тумблер вкл/выкл + поле «за сколько часов» (дефолт 2). Прогон cron'ом, идемпотентно.
