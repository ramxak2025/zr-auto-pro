# Фокус форм и каталог заказа поставщику — 2026-10-03

## Подтверждённые причины

- WEB: эффекты `Modal` и `Drawer` зависели от `onClose`. Обычный inline-обработчик менялся при каждом вводе символа; cleanup возвращал фокус на кнопку открытия, затем таймер фокусировал панель. Общий `useDialogFocus` теперь привязан к открытию, а актуальный callback читает через ref. Уже сфокусированное поле не перебивается таймером открытия.
- WEB: Касса и заказ поставщику запрашивали только первую страницу из 1000 товаров. В разрешённой read-only диагностике GasProfi на основном складе найдено 2813 товаров, включая 111 в ветке «БАЛЛОНЫ»; в первой тысяче по имени нет ни одного из этих 111 товаров.
- MOBILE: старый `ProductPickerModal` строил чип `БАЛЛОНЫ` с `trim`, но фильтровал исходную категорию по префиксу `БАЛЛОНЫ/`. Импортированные пути вида `БАЛЛОНЫ / Тороидальные` не проходили. У GasProfi 2495 товаров имеют пробелы у `/`; ветка баллонов состоит из 17 комплектующих, 55 тороидальных и 39 цилиндрических товаров. Отдельных записей этих папок в `warehouse_categories` нет: дерево нужно строить из категорий товаров.

Диагностика использовала только агрегаты в транзакции `BEGIN READ ONLY` с `statement_timeout=5s` и `ROLLBACK`. Данные и схема production не изменялись.

## Изменения

- `shared/api/productCatalog.ts` последовательно читает все страницы до `total`, учитывает возвращаемый сервером `limit` и не кеширует оборванную загрузку как полный каталог. Все владельцы общих кешей Кассы/пикера используют этот загрузчик, включая mobile login prefetch.
- `products.service.ts` сортирует страницы по имени и id, чтобы одинаковые имена имели устойчивый порядок.
- `shared/utils/productFolders.ts` строит одинаковое дерево для WEB/MOBILE, нормализуя пробелы сегментов только при отображении. Исходные категории не переписываются. Поддерживаются пустые папки и их порядок.
- Заказ поставщику WEB использует кассовый `ProductPickerDrawer`; MOBILE — кассовый `ProductPickerScreen` с переходами по уровням папок. В заказе показываются закупочные цены, выбранные товары и итог закупки. Доступен выбор склада; уменьшение количества в mobile сохраняет уже принятое количество.
- Старый mobile modal также исправлен: другие использующие его потоки получают полный каталог и корректные фильтры. При смене склада предыдущий список не показывается под новым названием склада.
