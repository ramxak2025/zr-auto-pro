# Импорт клиентов и автомобилей

Документация на функционал массового импорта клиентов и их автомобилей из Excel/CSV в Autexa.

> **Что НЕ импортируется**: сотрудники, пользователи, роли, пароли, услуги, товары, чеки, расписание. Только клиенты и привязанные к ним авто.

---

## 1. Цель

Дать владельцу автосервиса возможность за один шаг загрузить большой реестр клиентов и их машин (например, после миграции с другой системы или из Excel-таблицы) — без ручного ввода и без риска получить дубликаты.

Импорт:

- группирует строки по телефону (один телефон = один клиент);
- автоматически распознаёт российский и иностранный госномер;
- обрабатывает «грязные» строки (без телефона, с непонятной моделью, с конфликтами имён) явно, через предпросмотр;
- работает в рамках одного автосервиса (tenant), без возможности случайно записать данные в чужую базу;
- идемпотентен: повторный запуск того же файла не плодит дубликатов.

---

## 2. Поддерживаемые форматы

- `.xlsx` — Excel 2007+ (рекомендуется);
- `.xls` — старый Excel;
- `.csv`, `.txt` — UTF-8 или Windows-1251 (определяется автоматически).

Разделитель CSV: `;` или `,` — не важно, парсер угадывает.

Лимиты:

- **до 30 000 строк** за один импорт (на бэкенде это `MAX_ROWS` в `backend/src/imports/dto/import-clients-cars.dto.ts`);
- размер JSON-полезной нагрузки до 50 МБ (общий лимит API);
- одна строка файла = один клиент + ноль или один автомобиль.

Если строк больше 30 000 — разбейте файл на части.

---

## 3. Структура колонок

Заголовки колонок угадываются автоматически. Точные имена не обязательны — на шаге «Колонки» можно сопоставить руками. Распознаются такие варианты:

| Каноническое имя         | Пример имени в файле                                | Что хранится                                                                          |
| ------------------------ | --------------------------------------------------- | ------------------------------------------------------------------------------------- |
| `source_row`             | `source_row`, `№`, `id`, `номер строки`             | Номер исходной строки в файле — используется в сообщениях об ошибках.                 |
| `client_name`            | `client_name`, `name`, `имя`, `клиент`, `ФИО`       | Имя/ФИО клиента.                                                                      |
| `phone`                  | `phone`, `телефон`                                  | Телефон в каноническом виде (`+7…`). Если есть, используется как основной.            |
| `phone_raw`              | `phone_raw`, `phoneraw`, `сырой телефон`            | Телефон, как был в исходнике. Используется как fallback, если `phone` пуст.           |
| `car_plate`              | `car_plate`, `plate`, `госномер`, `номер авто`      | Госномер.                                                                             |
| `car_model`              | `car_model`, `model`, `марка`, `модель`             | Марка и модель.                                                                       |
| `notes`                  | `notes`, `пометки`, `качество`, `warnings`, `issue` | Технические пометки качества данных от источника, см. п.5.                            |
| `original_client_text`   | `original_client_text`, `original`, `raw`, `исх.`   | Исходная сырая строка клиента (для аудита). Не сохраняется в основные поля.           |

**Обязательные** поля для импорта строки: `client_name` и `phone` (или `phone_raw`).
Остальные — опциональные.

## 4. Пример CSV

```
source_row;client_name;phone;phone_raw;car_plate;car_model;notes;original_client_text
1;Иванов Иван;+79991234567;8 (999) 123-45-67;А123АА77;Toyota Camry;;Иванов Иван 89991234567 А123АА77 Тойота камри
2;Иванов Иван;+79991234567;8 (999) 123-45-67;В456ВВ99;Lada Granta;same_phone_different_plate;
3;Петров Пётр;;;Е789ЕЕ77;Kia Rio;no_phone;
4;Сидоров;+79007770000;9007770000;Х001ХХ50;;unclear_car_model;
5;Foreign Driver;+995555111222;+995 555 111 222;BG-3845-PA;BMW 3;foreign_plate;
```

После импорта:
- строки 1 и 2 → один клиент **Иванов Иван** с двумя авто (`А 123 АА 77` Toyota Camry, `В 456 ВВ 99` Lada Granta);
- строка 3 → пропущена (нет телефона);
- строка 4 → клиент **Сидоров** с авто `Х 001 ХХ 50` (модель = «Не определено», оригинал — в `cars.comment`);
- строка 5 → клиент с иностранным номером, импортируется с warning, нормализованный плате — `BG-3845-PA`.

CSV-шаблон с примерами скачивается кнопкой «Шаблон CSV» на странице импорта (или GET `/api/imports/clients-cars/template`).

## 5. Правила обработки

### 5.1. Группировка «один телефон → один клиент → несколько авто»

- Строки с одинаковым нормализованным телефоном объединяются в одного клиента.
- Все разные `car_plate` под этим телефоном становятся отдельными машинами этого клиента.
- Если на один телефон в файле приходят разные `client_name`, выбирается **наиболее частое** имя, остальные показываются в предпросмотре как warning `multiple_name_candidates`.
- Если клиент с этим телефоном **уже есть** в базе автосервиса — новые авто добавляются к нему, имя не перезаписывается. Конфликт имени отображается как warning `name_conflict_same_phone`.

### 5.2. Строки без телефона (`no_phone`, `invalid_phone`)

**Всегда пропускаются.** Клиент в Autexa обязан иметь телефон (поле `clients.phone NOT NULL`). Такие строки попадают в раздел «Пропущенные строки» в предпросмотре и в итоговом отчёте — владелец может потом добавить их вручную.

### 5.3. Иностранные/нестандартные номера (`foreign_plate`)

- По умолчанию **импортируются с warning**.
- На шаге «Колонки» есть чекбокс «Импортировать иностранные/нестандартные номера» — снимите, если хотите пропускать.
- Cyrillic look-alikes транслитерируются в латиницу: `АМ36Сu857` → `AM36CU857`. Это нужно, чтобы дедуп работал стабильно.
- При создании в `cars.comment` добавляется пометка «Импорт: иностранный/нестандартный номер».

### 5.4. Непонятная модель (`unclear_car_model`)

- Если в `car_model` пусто, либо текст похож на «Необходимо добавить автомобиль», «unclear», «не определено» и т.п., либо `notes` содержит `unclear_car_model` — авто всё равно создаётся.
- В `cars.make_model` подставляется `Не определено`.
- Исходный текст модели (если был и не похож на placeholder) сохраняется в `cars.comment` с префиксом «Импорт: модель — …».
- На предпросмотре показывается warning.

### 5.5. Имя в нижнем регистре (`name_lowercase`) и all-caps

Имя нормализуется к виду «Имя Отчество» (первая буква каждого слова — заглавная). `ИВАНОВ ИВАН` → `Иванов Иван`. Если имя уже смешанного регистра — оставляем как есть.

### 5.6. Без имени (`no_name`)

- Если имя отсутствует — строка не пропускается, но создаётся warning.
- В случае создания нового клиента имя ставится `Клиент` (плейсхолдер).
- Лучше указать имя явно перед импортом — но это soft warning.

### 5.7. Дубликаты внутри файла

- Один и тот же госномер у одного и того же клиента в файле → дубль молча схлопывается в один + warning `duplicate_in_file`.
- Один и тот же госномер у **разных** клиентов в файле → к каждому клиенту привязывается **только первый**, остальные пропускаются с warning `duplicate_in_file`.

### 5.8. Дубликаты против существующей базы (`plate_belongs_to_other_client`)

- Если госномер из файла уже привязан в базе к **другому** клиенту — авто **не перезаписывается** и **не переносится** молча. Строка попадает в раздел «Ошибки уровня строки» на предпросмотре. На confirm-шаге она тоже пропускается и отображается в итоговом отчёте.
- Если же госномер уже у того же клиента (что мы будем создавать или к кому привяжемся по телефону) — это нормальная идемпотентность: машина просто не создаётся повторно.

## 6. Дедупликация

| Что               | Ключ дедупа                                                                            | Поведение                                                                |
| ----------------- | -------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| Клиенты           | `tenant_id + normalized_phone` (`+7…`)                                                 | Существующий клиент переиспользуется, имя не переписывается.             |
| Автомобили        | `tenant_id + UPPER(plate_number) без пробелов/дефисов/слешей`                          | Если plate уже есть у того же клиента — skip. Если у другого — конфликт. |
| Внутри файла      | По `phoneKey` (для клиентов) и `plateKey` (для авто) — выше                            | Дубликаты внутри файла схлопываются.                                     |

Plate-нормализация одинакова и при импорте, и в lookup-эндпоинтах:

```
"Р 332 РА 05" → "Р332РА05"
"P332PA05"     → "Р332РА05"  (Latin → Cyrillic look-alikes)
"АМ36Сu857"    → foreign:    "AM36CU857"
"BG-3845-PA"   → foreign:    "BG3845PA"
```

---

## 7. Tenant isolation

- `tenant_id` **никогда** не берётся из файла или из тела запроса.
- На бэкенде он извлекается только из JWT через `@CurrentUser()` (`backend/src/imports/imports.controller.ts`).
- Клиенты создаются с `tenant_id` текущего пользователя; авто наследуют tenant от своего клиента.
- Невозможно записать данные в чужой автосервис, даже если в полезной нагрузке указать другой `tenantId`.

## 8. Permissions

Импорт доступен только ролям с правом администрирования сервиса:

- `superadmin` (владелец платформы);
- `director` (владелец автосервиса);
- `admin` (администратор автосервиса).

Роль `master` (мастер/исполнитель) не видит ни кнопки «Импорт», ни маршрута `/clients/import`. Если попытается обратиться напрямую — `RolesGuard` вернёт 403.

Гард: `@UseGuards(JwtAuthGuard, RolesGuard)` + `@Roles('director','admin','superadmin')` на `POST /imports/clients-cars/preview` и `POST /imports/clients-cars/confirm`.

GET `/imports/clients-cars/template` доступен любому залогиненному (это просто статический CSV).

## 10. Web UI flow

1. Открыть `Клиенты` → кнопка **«Импорт»** в правом верхнем углу (видна только director/admin/superadmin).
2. Шаг 1 — **Загрузка**. Drag-and-drop или выбор файла .xlsx/.xls/.csv. Кнопка «Шаблон CSV» рядом скачивает образец.
3. Шаг 2 — **Колонки**. Авто-сопоставление по заголовкам, dropdown для ручной правки. Просмотр первых 5 строк в выбранном маппинге. Чекбокс «Импортировать иностранные/нестандартные номера».
4. Шаг 3 — **Проверка**. Карточки сводки (Всего строк / Клиентов / Авто / Пропущено), раскрывающиеся секции «Пропущенные строки», «Предупреждения», «Ошибки уровня строки», список первых 20 клиентов после группировки.
5. Шаг 4 — **Подтверждение**. Кнопка «Подтвердить импорт» → confirm → итоговый отчёт с `importRunId`.

Всё парсится на клиенте через `xlsx` (уже в зависимостях фронта). На сервер уходит только JSON.

## 11. Mobile

Mobile UI для импорта намеренно **не делается** — это десктопная операция (большие файлы, mapping таблиц).

Импортированные клиенты и авто **видны на iOS/Android** автоматически — мобилка ходит в те же `/clients`, `/cars` endpoints. После импорта пулл-ту-рефреш (или 30-сек staleness React Query) подтянет новые записи. Поиск клиента/авто по госномеру в кассе работает как раньше.

## 12. База данных

Новая таблица `import_runs` (миграция `backend/migrations/025_import_runs.sql`):

```sql
CREATE TABLE IF NOT EXISTS import_runs (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    tenant_id UUID NOT NULL REFERENCES tenants(id) ON DELETE CASCADE,
    user_id UUID REFERENCES users(id) ON DELETE SET NULL,
    kind TEXT NOT NULL,                       -- 'clients_cars' for now
    total_rows INTEGER NOT NULL DEFAULT 0,
    created_clients INTEGER NOT NULL DEFAULT 0,
    reused_clients INTEGER NOT NULL DEFAULT 0,
    created_cars INTEGER NOT NULL DEFAULT 0,
    skipped_rows INTEGER NOT NULL DEFAULT 0,
    payload JSONB NOT NULL DEFAULT '{}'::jsonb,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE INDEX IF NOT EXISTS idx_import_runs_tenant_created
    ON import_runs (tenant_id, created_at DESC);
```

Каждый успешный confirm создаёт одну запись:
- `payload.skipped` — список строк, которые были пропущены (с причинами);
- `payload.issues` — все warnings/errors уровня строки;
- `payload.options` — опции импорта (`allowForeignPlates`).

Это нужно, чтобы владелец потом мог разобраться, почему какие-то строки не попали в систему, без повторной загрузки файла.

Существующие таблицы `clients` и `cars` **не меняются** — никаких новых колонок. Импорт пишет в стандартные поля.

## 13. Production deploy steps

1. Слить ветку в master через PR (после ручной проверки).
2. CI прогонит typecheck + lint + build для backend, frontend, mobile.
3. Деплой backend (через webhook auto-deploy или вручную) — при старте `MigrationRunner` применит `025_import_runs.sql` идемпотентно (`CREATE TABLE IF NOT EXISTS`).
4. Деплой frontend (статикой через nginx-контейнер).
5. Никаких новых env-переменных. Никаких изменений в `docker-compose.yml`. Никаких ручных `psql` шагов.

Откат:
- В коде — `git revert` коммита.
- В БД — таблица `import_runs` остаётся (это просто аудит). Можно удалить вручную: `DROP TABLE IF EXISTS import_runs;` — но обычно не нужно.

## 15. Безопасность

- Парсинг xlsx/csv — только в браузере. На сервер уходит **JSON** с уже извлечёнными полями. Это снимает класс RCE-уязвимостей в xlsx-парсерах на бэке.
- DTO + `class-validator` (`ValidationPipe({ whitelist: true })` глобально в `main.ts`) отсекают любые посторонние поля.
- Все запросы используют `pg` parameterized queries — SQL injection невозможен.
- `tenant_id` берётся **только** из JWT — невозможно записать данные в чужой автосервис.
- Сами по себе телефоны и госномера — это PII; они хранятся в `clients`/`cars` как раньше, и в `import_runs.payload` хранится только список `sourceRow + reason + message` (без сырых PII).
- `RolesGuard` блокирует не-админов на уровне HTTP.

---

## 16. Ограничения и известные нюансы

- На больших файлах (15-25k строк) шаг confirm выполняется по одной транзакции с per-row INSERT'ами. На локальном Postgres это занимает 30-60 секунд. Веб-фронт показывает спиннер и не таймаутится. Если в проде будет таймаут на nginx — увеличьте `proxy_read_timeout`.
- При совсем гигантских файлах (>30k) надо разбить вручную — стоит явный гард в DTO.
- `import_runs.payload` не показывается в UI — это аудит для разработчика. История импорта в виде раздела на сайте — отдельная задача (P2).
- Mobile-импорт не делается. Это сознательно.
